# Notesis C++ 이전 진행표

## 기준과 현재 상태

- 기준: 정식 Notesis **0.93.0 (233)**, `581ee53`.
- 첫 배포: **0.93.0-lab.cpp.1 (234)**, **1/4단계**.
- 패키지: `com.notesis.lab`. 정식 앱의 데이터 디렉터리에 접근하지 않습니다.
- 정식판의 Material 화면, 카드에서 열리는 노트, 뒤로 밀기, 폴더·메뉴 모션과 0.93.0의 Markdown 블록 편집기·AI 첨부·명령 코어를 유지합니다.
- 1/4은 단계 번호이며 전체 코드의 25%가 이전되었다는 뜻은 아닙니다.
- **전체 C++ 이전이 완료된 앱이 아닙니다.** Kotlin UI와 AndroidX Ink 연결은 남아 있습니다.
- C++ 코드가 존재하는 것, 실제 실행 경로에서 쓰이는 것, 실기기에서 빨라진 것은 각각 다릅니다.

## 4단계

| 단계 | 목표 | 현재 상태 | 완료를 판단할 조건 |
|---|---|---|---|
| 1 | 일괄 연산 코어와 기존 형식 해석 | 이번 Lab에서 구현 | 원본 알고리즘과 결과 일치, 손상 입력 검사, JNI 회귀시험, 앱 빌드 |
| 2 | 문서 모델·Undo·Redo·저장·로딩의 C++ 소유권 | 미구현 | v1~v4 및 백업 왕복, 원자 저장·복구·취소·전역 예산, 기존 앱과 호환 |
| 3 | 펜·터치·캔버스·타일 스케줄링 이전 | 미구현 | 펜 표시→확정 전환에 빈 프레임 없음, 지우개·선택·레이어·PDF·확대 동등성, API 29~36 실기기 검증 |
| 4 | UI 전반과 플랫폼 연결 재구현·통합 | 미구현 | 현재 UI·모션·접근성·IME·뒤로가기·멀티윈도·권한·공유·인쇄·위젯·백업·인식·업데이트 동등성 |

4단계는 Compose 화면을 네이티브 UI/렌더러로 다시 구현하는 작업입니다. Kotlin 파일 확장자를 바꾸거나 JNI로 감싸는 작업으로 완료되지 않습니다. Android의 Activity, IME, WebView, ML Kit 등 JVM API에는 얇은 플랫폼 연결이 남을 수 있습니다. 그 범위는 별도로 기록해야 합니다. 이 문서는 이후 단계가 자동 실행·예약되었다는 뜻이 아닙니다.

## 이번에 실제로 C++로 실행하는 부분

`note_core.cpp` / `note_core_jni.cpp`:

1. 필기 시작 정지 구간 탐지와 제거 마스크 계산.
2. 접촉·펜을 뗄 때의 짧은 역방향 돌기 탐지.
3. 획 중간 정지·반전 구간 접기와 원래 인덱스로의 복원.
4. 로딩한 펜 입력, 확정한 펜, 그 밖의 자유곡선의 세 후처리 모드.
5. NTSS v1~v4 획 파일의 헤더·개수·길이·범위 해석, 메타데이터와 입력 위치 인덱스 생성.

Android에서는 `CppCore.keepMask`가 일정 길이 이상의 획을 한 번의 JNI 호출로 넘깁니다. 32점 미만은 호출 비용을 피하려고 기존 Kotlin으로 처리합니다. 디지타이저 이벤트마다 JNI를 호출하지 않습니다. 라이브러리 준비 중, 비활성, 안전 모드, 지원 범위 밖이면 기존 경로입니다.

페이지 인덱스는 8MiB 이하 파일만 대상으로 합니다. 직접 버퍼는 동시에 하나만 빌리고, 다른 로드는 기존 스트리밍 경로를 사용합니다. 큰 파일·손상된 레코드·지원하지 않는 버전도 기존 경로로 넘깁니다. Android가 메모리를 요구하면 사용 중이지 않은 버퍼 참조를 해제합니다. 실제 메모리 회수 시점은 런타임에 달려 있습니다.

파일을 여는 I/O, Brush 생성, AndroidX Ink 입력 해독·메시 생성, UI 반영은 이번에 이전하지 않았습니다. 쓰기는 기존 구현과 바이트 형식을 그대로 사용합니다. 읽기만으로 파일을 다시 저장하지 않습니다.

기존 C++ 공간 인덱스와 부분지우개 기하 연산도 유지합니다. 자체 표시 버퍼 실험은 계속 기본 꺼짐입니다.

## 비교와 확인

설정 → 진단 → Native code에서 **C++ bulk processing**을 바꿉니다. 로딩 비교는 변경 후 앱을 완전히 종료했다 다시 시작합니다. 열린 노트의 캐시는 새 읽기를 생략할 수 있습니다.  C++ 코어가 Loaded인지와 후처리·페이지 해석 횟수가 증가하는지 확인합니다. 단순히 설정을 켰다는 이유만으로 모든 작업이 C++로 실행되었다고 판단하지 않습니다.

1. 정식판에서 시험용 노트를 내보내고 Lab에 가져옵니다. 두 앱의 저장 공간은 별개입니다.
2. 같은 노트·확대율·화면 주사율·배터리 상태에서 C++ 켜기/끄기를 번갈아 비교합니다.
3. 실제 펜으로 100획 이상 쓰고, 부분지우개·Undo·Redo·레이어·저장 후 재열기를 확인합니다.
4. 빽빽한 노트 열기·페이지 이동·확대·팝업·뒤로가기를 기록합니다.
5. 60Hz/120Hz, 절전 켜기/끄기, 차가운 상태/연속 사용을 나누어 확인합니다.

임시 획을 버리는 기존 scripted benchmark는 저장·Undo 비용을 재지 않습니다. 이번 변경의 효과 전체를 판단하는 데에는 실제 저장되는 필기도 필요합니다.

호스트 C++ 시험은 주소·정의되지 않은 동작 검사와 잘못된 입력을 다룹니다. JVM JNI 시험은 기존 Kotlin 계산과 무작위 입력의 결과를 비교합니다. 호스트 마이크로벤치마크는 파일 I/O·JNI·Ink 해독·메시·UI·표시 시간을 제외하므로 앱 성능 개선율이 아닙니다. 실기기에서의 지연·발열·배터리 개선은 아직 측정하지 않았습니다.
