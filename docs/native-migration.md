# Notesis C++·Rust 이전 작업

기준은 정식 **0.94.0 (234)**, `82ef444`입니다. 작업 브랜치는
`codex/native-core-v2-0.94.0`이며 정식 main의 코드와 데이터는 변경하지 않습니다.

목표는 C++·Rust가 앱의 대부분을 담당하도록 바꾸는 것입니다.
**현재 그 목표가 완료된 상태는 아닙니다.** Kotlin/Compose 화면과 캔버스
컨트롤러가 여전히 소스의 큰 부분을 차지합니다. 이번 공통 엔진 작업을
전체 이전이나 이전율 50%로 표시하지 않습니다.

## 현재 실제 실행 경로

| 영역 | 담당 | 상태 |
|---|---|---|
| 공간 인덱스·부분지우개 기하 | C++ | 기존 구현 유지 |
| 획 접촉·종료 돌기·정지 구간 후처리 | C++ | 앞선 Lab 구현 유지 |
| NTSS v1~v4 파일 읽기·경계 확인·커서 | Rust | 앱의 페이지 읽기에서 사용 |
| v4 전체 저장·임시 파일·완료 후 교체 | Rust | 앱의 전체 페이지 저장에서 사용 |
| 증분 저장·미완성 꼬리 복구·중단 시 롤백 | Rust | 앱의 획 추가 저장에서 사용 |
| Markdown Undo/Redo·타자 묶기·선택 위치 | Rust | 새로 열리는 Markdown 편집기에서 사용 |
| JNI·AndroidX Ink 공개 API 연결 | Kotlin·C++ | Ink 입력 해독과 Brush/Stroke 생성은 기존 API 사용 |
| Document/Page 모델·메타데이터 JSON·저장 스냅샷·렌더 상태 | Kotlin | 아직 이전하지 않음 |
| 펜·손 제스처·캔버스 컨트롤러·타일 작업 | Kotlin·기존 라이브러리 | 아직 전면 이전하지 않음 |
| Compose 화면·팝업·사이드바·설정·터미널 UI | Kotlin | 아직 이전하지 않음 |
| 권한·IME·WebView·공유·위젯·업데이트 | Android 플랫폼 연결 | 최소 연결 코드가 필요 |

비교 스위치를 끄거나 라이브러리가 준비되지 않으면 기존 Kotlin 경로를
사용합니다. 기존 경로가 남아 있는 사실도 전체 언어 비율 계산에 포함합니다.
외부 라이브러리, 생성 코드와 테스트를 더해 네이티브 비율을 높이지 않습니다.

## UI 이전 결정점

현재 기능·모션을 유지한 채 네이티브 UI를 만들 경우 기능별 대조와 검증을
마친 화면부터 바꿔야 합니다. 이 동안 Kotlin 화면이 남습니다.

별도 네이티브 UI를 먼저 완성하고 기능을 순차 복구할 경우 빠르게 네이티브
소스 비중을 높일 수 있지만, 처음에는 기존 기능 중 일부가 빠집니다.
그 상태를 현재 Notesis와 동등한 완성판으로 배포하지 않습니다.

원래 앱의 기능을 빼고 비율만 높이는 방식은 기본값으로 택하지 않습니다.
네이티브 UI의 범위가 정해지기 전에도 공통 문서·필기 엔진 이전은 진행할 수 있습니다.

## 검증 범위

Rust 단위 시험은 v1~v4, 모든 위치의 잘림, 잘못된 길이·개수, 저장 중단,
미완성 추가 저장 복구, UTF-16 이력과 시간 값 래핑을 확인합니다.
JNI 시험은 기존 Java 형식 및 C++ 인덱스와의 대조, 동시 읽기, 닫힌 핸들,
잘못된 자원 종류, 임의 편집·Undo/Redo 동작을 확인합니다.

빌드·시험 결과와 실기기 결과는 다릅니다. 현재 필기 지연, 프레임, 발열,
배터리 개선율을 실기기에서 측정하지 않았습니다.
