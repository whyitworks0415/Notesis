# Notesis 0.38.2 (101)

PDF 노트와 일반 노트를 여는 속도를 크게 개선했습니다.

## 변경 사항

### PDF 노트: 링크 찾기를 여는 경로에서 뺐습니다

- 지금까지 PDF가 있는 노트를 열 때마다 PDF 안의 링크(목차·페이지 이동·웹 링크)를 찾느라 **PDF 전체를 PDFBox로 처음부터 끝까지 읽었고**, 이 작업이 끝나야 노트가 열렸습니다. 쪽수가 많거나 큰 PDF일수록 몇 초씩 걸렸습니다.
- 이제 노트는 바로 열리고, 링크는 백그라운드에서 낮은 우선순위로 찾습니다. 찾은 링크는 노트 폴더의 작은 파일(`pdf-links.json`)에 저장해서, **두 번째부터는 PDF를 다시 읽지 않습니다**. PDF 파일이 바뀌면(크기·수정 시각) 다시 찾습니다.
- 링크를 찾는 동안에는 PDF 전체를 메모리에 올리지 않고 임시 파일을 사용해, 필기·화면 그리기와 메모리를 다투지 않습니다.
- 썸네일 만들기·내보내기·검색 색인처럼 링크가 필요 없는 곳에서 PDF를 열 때도 링크를 찾던 것을 없앴습니다.
- 노트 정보와 PDF를 차례로 열던 것을 동시에 엽니다.

### 필기: 여러 코어로 동시에 불러오기

- 저장된 필기는 입력값만 저장되어 있어 열 때마다 획의 모양을 다시 계산합니다. 이 계산을 한 코어에서 획 하나씩 하던 것을, **여러 코어에서 나눠 동시에** 하도록 바꿨습니다. 필기가 많은 페이지일수록 빨라집니다(획 48개 이상일 때).
- 같은 펜·색·굵기의 획은 브러시를 하나만 만들어 함께 씁니다.
- 손상된 획 하나 때문에 그 뒤의 획을 모두 못 읽던 것을, 그 획만 건너뛰도록 바꿨습니다.

### PDF 가져오기

- Android 15 이상에서 PDF를 가져올 때 모든 페이지의 글자를 검색용으로 뽑느라 새 노트가 늦게 열리던 것을, 노트를 먼저 열고 글자는 백그라운드에서 뽑도록 바꿨습니다. 가져온 직후 잠깐은 PDF 본문 검색 결과가 덜 나올 수 있습니다.

## 참고

- 이 환경에는 Android SDK가 없어 빌드와 단위 테스트는 GitHub Actions에서 수행합니다. 실제 기기에서 속도를 재 보지는 못했습니다.
