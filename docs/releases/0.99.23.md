# Notesis 0.99.23 (264)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

## 유리 스킨에서 필기가 Material보다 느리던 원인을 고쳤습니다
- **원인:** 유리는 노트 페이지를 배경으로 씁니다. 그런데 그 배경이 페이지의 "그림"이 아니라 페이지 자체(렌더 노드)를 가리키고 있었습니다. 그래서 획을 확정할 때, 스크롤 프레임마다, 페이지 조각이 도착할 때마다 툴바, 툴바 버튼 하나하나, 시계 같은 모든 유리 면이 블러와 렌즈를 GPU에서 다시 계산했습니다. 펜으로 쓰는 동안에는 유리를 멈춰 두도록 설계되어 있었지만 이 때문에 지켜지지 않았습니다. Material에는 유리가 없어 이 비용이 없습니다.
- **수정:** 페이지를 노드 세 개에 번갈아 기록합니다. 유리가 마지막으로 받은 노드는 그대로 두고, 페이지는 다른 노드에 기록합니다. 그래서 펜으로 쓰는 동안과 쓴 직후(0.7초)에는 유리가 아무것도 다시 계산하지 않습니다. 쉬는 동안 페이지가 바뀌면 그때 한 번 따라옵니다. 그림을 복사하지 않으므로 메모리는 늘지 않습니다.
- 유리를 쓰는 동안 GPU가 덜 일하므로 발열도 줄어들 것으로 봅니다(측정은 하지 않았습니다).

## 새 설정: 스크롤할 때 유리도 따라가기
- **설정 → 모양 → Glass**에 있습니다. 기본은 켜짐으로, 지금처럼 스크롤하는 동안 유리 아래로 페이지가 움직입니다.
- 끄면 스크롤이 멈출 때까지 유리가 직전 그림을 유지합니다. 스크롤 프레임마다 유리를 다시 그리지 않아 GPU와 배터리 부담이 줄어듭니다.
- 켜 두어도 펜으로 쓰는 동안에는 항상 멈춰 있습니다.

## 첫 팝업이 멈칫하던 것
- 유리를 쓰는 스킨이면 앱이 시작해 한가할 때 렌즈 셰이더를 미리 만들어 둡니다. 화면 밖 8픽셀 크기로 한 번 그려 GPU 프로그램까지 준비합니다. 첫 팝업을 열 때 그 비용을 내지 않습니다.

## C++/Rust나 GPU 이전에 대하여
- 이번 문제의 원인은 계산 코드가 아니었습니다. GPU가 같은 유리를 필요 없이 반복해서 다시 그리는 것이었습니다. 그래서 언어를 바꾸기보다 다시 그리지 않게 했습니다. 펜 경로의 무거운 계산(지우개 기하, 검색 트리, 잉크 묶음)은 이미 C++ 커널로 되어 있습니다.

## 어떻게 확인했나
- CI의 릴리스 빌드, Lint, 단위 테스트, 스크린샷 테스트로 확인합니다. 새 테스트는 유리가 잡고 있는 노드에는 절대 기록하지 않는다는 규칙입니다.
- **태블릿에서 확인하지 못했습니다. 지연과 발열은 측정하지 않았습니다.** 기기에서 비교하려면 `assembleBench`와 `tools/performance-lab/device_replay.py`로 Material과 iOS를 같은 필기로 재 보면 됩니다.

## 하지 않은 것 / 바뀐 점
- 펜으로 쓰는 동안에는 툴바 아래로 비치는 페이지가 방금 쓴 획을 바로 보여 주지 않습니다. 0.7초 쉬면 따라옵니다. 원래 설계대로입니다.
- 유리 모양, 연속 곡률 모서리, 두 겹 구성은 바꾸지 않았습니다.

## 태블릿에서 해 볼 것
1. iOS 스타일로 빠르게 여러 줄 쓰기 → Material과 비교해 펜이 따라오는 느낌이 비슷한지.
2. 툴바 아래에서 쓰고 잠깐 쉬기 → 쉰 뒤 유리에 방금 쓴 획이 비치는지.
3. 스크롤 → 유리 아래 페이지가 움직이는지. 설정에서 끄면 멈춘 뒤에 바뀌는지.
4. 앱을 처음 켜고 첫 팝업이 덜 멈칫하는지.
5. 오래 쓸 때 전보다 덜 뜨거운지.
