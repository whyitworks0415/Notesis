# Notesis 0.98.0 (239)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

> ⚠️ 0.91.0부터 앱은 **Material 화면만** 씁니다. Liquid glass·Glassmorphism을 계속 쓰려면 0.90.28에 머무르세요.

열어 둔 노트에도 에이전트의 변경이 바로 보이고, 앱 안 사이드바에서 에이전트에게 물을 수 있고, Termux를 옆에 띄울 수 있습니다. 에이전트가 쓰는 토큰도 더 줄였습니다.

## 바뀐 점

### 열어 둔 노트에 바로 반영
- 지금까지는 화면에 열린 노트를 에이전트·터미널이 바꾸지 못했습니다(화면이 가진 사본이 변경을 덮어쓰기 때문). 이제는 변경이 오면 **화면이 지금 모습을 먼저 저장하고 → 아주 잠깐 멈추고 → 변경을 적용한 뒤 → 그 자리에서 노트를 다시 읽습니다.** 보던 쪽과 확대 상태는 그대로입니다.
- 멈추는 동안에는 노트 위에 "에이전트의 변경을 반영하는 중…"이 뜨고 터치가 막힙니다(그 사이에 쓴 획이 사라지지 않게). 펜으로 쓰고 있는 중이면 획이 끝날 때까지 기다립니다(최대 4초).
- Markdown 노트도 같습니다. 반영된 변경은 편집기의 되돌리기로도 되돌릴 수 있습니다.
- 에이전트가 노트 이름을 바꾸면 열린 화면도 새 이름으로 저장합니다.
- 그대로인 것: **분할 화면의 다른 칸·참고 패널에 열린 노트는 읽기만** 합니다. 화면에 열린 노트를 **휴지통으로 보내는 것은 거절**합니다. 폴더·태그·즐겨찾기·라벨은 열려 있어도 바로 바뀝니다.
- 다시 읽으면 그 화면의 실행 취소 기록은 비워집니다. 에이전트의 변경은 `undo`나 변경 카드의 되돌리기로 되돌립니다.

### 앱 안 에이전트 사이드바
- 노트 화면의 빠른 동작과 첫 화면 메뉴에 **에이전트에게 묻기**가 생겼습니다. 오른쪽에 사이드바가 열리고, 노트는 그 옆에서 계속 쓸 수 있습니다.
- 다른 앱(Termux)의 화면을 앱 안에 넣을 수는 없습니다. 그래서 사이드바는 Termux에 **"이 에이전트를 한 번 실행해 줘"라고 요청**하고 답을 받아 보여 줍니다(Termux의 RUN_COMMAND). 기다리는 동안 에이전트가 Notesis에 보내는 명령(`› pdf info …` 같은)이 실시간으로 보입니다.
- 지금 열린 노트가 요청에 자동으로 붙어서 "이 노트"라고만 해도 됩니다.
- Claude Code와 OpenCode는 대화를 이어 갑니다. 새 대화 버튼으로 새로 시작합니다. Codex·Gemini CLI는 요청마다 새로 시작합니다.
- 처음 쓸 때 **"Termux에서 명령 실행" 권한**을 묻습니다. 그리고 Termux가 다른 앱의 요청을 받도록 **설정 스크립트를 한 번 다시 실행**해야 합니다(`allow-external-apps = true`를 켜고, 요청을 받아 에이전트에게 넘기는 작은 도우미 `~/.notesis/ask`를 Debian에 둡니다). 이 권한을 준 앱만 Termux에 명령을 보낼 수 있습니다.
- 보안: 입력한 글은 명령줄에 들어가지 않고 표준 입력으로만 전달되어, 글 안의 따옴표나 `$( )`가 명령이 되지 않습니다(시험으로 확인). Claude Code는 Notesis 도구만 묻지 않고 쓸 수 있게 했고, 노트 변경은 여전히 "먼저 묻기/바로 하기" 설정을 따릅니다. Gemini CLI는 Notesis 연결만 신뢰(`trust`)로 표시해서 묻지 않고 쓸 수 있게 했습니다.

### Termux를 옆에·창으로
- 에이전트 패널의 **Termux를 옆에 열기**(분할 화면)와 **창으로 열기**, 사이드바 위쪽의 Termux 버튼. 창으로 열기는 기기가 창 모드(삼성 팝업 보기 등)를 줄 때만 창으로 뜨고, 아니면 전체 화면으로 열립니다.

### 토큰 줄이기
- 노트 목록·읽기에서 **빈 항목을 뺐습니다**(빈 폴더, 빈 태그, 손글씨 노트의 kind).
- 목록의 id를 **서로 구별되는 만큼만 짧게**(보통 8자) 줍니다. 모든 명령이 짧은 id를 받습니다.
- `note read 노트 --since 수정시각`: 그 뒤로 안 바뀌었으면 "unchanged"만 답합니다. `notes list --since`는 그 뒤에 바뀐 노트만.
- `notesis_help`는 기본으로 명령과 규칙만 주고, 요령은 `topic: "recipes"`, 명령 묶음은 `topic: "pdf"`처럼 따로 받습니다.
- 기본 읽기 양을 2만 → 1만 2천 자, 목록 기본 개수를 50 → 30개로 줄였습니다(필요하면 옵션으로 늘림).

## 어떻게 확인했나
- 단위 테스트 전체 통과(로컬, 네이티브 검사 포함). 새로 시험한 것:
  - 열린 노트: 변경 묶음 전체에 한 번만 화면을 멈추고 변경 뒤 다시 읽으라고 알리는지, 실패한 묶음은 다시 읽지 않는지, 되돌리기도 같은지, 멈출 수 없는 화면이면 거절하는지.
  - 실제 노트 파일로, 화면이 아직 저장하지 않은 내용을 먼저 쓰고 그 위에 변경이 들어가는지(덮어쓰지 않는지).
  - 사이드바 요청: 명령줄은 고정된 낱말뿐이고, 도우미가 따옴표·`$( )`가 든 글을 한 덩어리 글로 에이전트에게 넘기는지(가짜 claude로).
  - 짧은 id, `--since`, 빈 항목 생략, 주제별 도움말.

## 하지 않은 것
- **태블릿에서 해 보지 않았습니다.** 다음은 기기에서만 알 수 있습니다:
  - 열린 노트를 다시 읽을 때 깜빡임, 위치가 정확히 그대로인지.
  - Termux의 RUN_COMMAND 권한 요청과 결과 받기, `proot-distro login`을 통한 실행, 표준 입력 전달.
  - 분할 화면 열기와 창으로 열기가 S6 Lite(One UI)에서 어떻게 뜨는지.
- 사이드바의 답은 다 끝나야 한 번에 옵니다(글이 흘러나오지 않음). 진행 상황은 에이전트가 보내는 Notesis 명령으로만 보입니다.
- 분할 화면의 다른 칸·참고 패널의 노트에는 아직 바로 반영하지 않습니다.

## 태블릿에서 해 볼 것
1. 에이전트 패널 → 이 태블릿에서 → **설정 스크립트를 다시 복사해 Termux에서 실행**(Termux가 Notesis의 요청을 받게 됨).
2. 노트를 연 채로 Termux의 Claude Code에게 "이 노트에 쪽 하나 추가해 줘" → 노트 위에 잠깐 문구가 뜨고 쪽이 바로 생기는지.
3. 노트 화면 빠른 동작 → **에이전트에게 묻기** → 권한 허용 → "이 노트의 목차를 PDF로 만들어 줘". 기다리는 동안 명령 줄이 보이는지, 끝나면 답이 오는지.
4. 에이전트 패널 → **Termux를 옆에 열기**: 반반 분할로 뜨는지. **창으로 열기**도.
5. 에이전트 패널 아래 **사용량**이 전보다 적게 늘어나는지(같은 요청 기준).
