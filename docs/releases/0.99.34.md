# Notesis 0.99.34 (275)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

0.99.33을 바탕으로 만들었습니다.

## 쓰는 중인 필기가 끊겨 그려지고 살짝 늦던 문제
### 원인으로 본 것
- 0.99.28에서 화면 주사율을 유지하려고, 펜이 닿아 있는 동안 앱 창 구석의 1픽셀을 매 프레임 바꿨습니다.
- 그런데 이 1픽셀이 앱 창 안에 있어서, 바꿀 때마다 **앱 화면 전체(Compose)가 매 프레임 다시 그려졌습니다**. 이 태블릿은 그때마다 시스템이 주사율 기록(스택 추적과 로그)까지 남깁니다.
- 펜 입력도 같은 UI 스레드로 들어옵니다. 그래서 펜 이벤트가 이 프레임들 뒤에서 기다리며 지연과 끊김을 만들 수 있었습니다.

### 바뀐 점
- 1픽셀을 **앱 창이 아닌 별도의 작은 화면(Surface)**으로 옮겼습니다.
  - 이 화면은 **자기 전용 스레드**가 매 프레임 새로 그립니다.
  - Android 11 이상에서는 패널의 최고 주사율을 직접 요청합니다.
  - 앱 창, Compose, UI 스레드는 펜을 쓰는 동안 아무것도 다시 그리지 않습니다.
- 펜을 떼면 바로 멈춥니다. 개발자 모드의 "화면 주사율 유지"로 끄고 켤 수 있습니다.

## 노트 밖 필기(화이트보드)가 많을 때 렉
### 원인으로 본 것
- 확대·축소를 끝낼 때마다, 화면에 보이는 노트 밖 필기를 새 배율에 맞게 다시 만들었습니다.
- 이 작업을 **UI 스레드에서 프레임마다 24획씩**, 전부 끝날 때까지 했습니다. 획이 많으면 그만큼 오래 버벅였습니다.
- 노트를 열어 노트 밖 필기가 처음 보일 때도 같은 방식이었습니다.

### 바뀐 점
- 다시 만드는 작업을 **전용 백그라운드 스레드**로 옮겼습니다. UI 스레드에서는 한 프레임에 2획까지만 바로 만들어, 방금 쓴 획은 곧바로 보입니다.
- 다시 만드는 동안에는 이전 그림을 그대로(배율만 맞춰) 보여 주고, 다 되면 한 번에 바꿉니다.
- 노트 밖에 새 획을 쓰면, 그 칸의 이전 그림 위에 새 획만 덧그려 둡니다. 칸 전체를 획 하나씩 다시 그리지 않습니다.
- 지운 획의 캐시를 함께 정리해 메모리가 쌓이지 않게 했습니다.

## 어떻게 확인했나
- 빌드, 축소(R8) 릴리스 빌드, Android 버전 검사(Lint), 네이티브 커널 점검, 전체 단위 테스트(157개 클래스)를 통과했습니다.

## 하지 않은 것 / 확인하지 못한 것
- **태블릿에서 직접 써 보거나 재 보지 않았습니다.** 원인은 코드와 0.99.16의 측정 기록(앱 프레임이 그릴 때마다 드는 비용)으로 추정한 것입니다.
- 그래도 끊기거나 늦으면, 개발자 모드에서 다음을 하나씩 바꿔 비교해 보시고 결과를 알려 주세요.
  - "화면 주사율 유지" 끄기·켜기
  - 예측 4ms ↔ 8ms
  - 펜 설정의 "쓰는 중인 획을 보여 주는 방식"을 호환으로 바꾸기

## 태블릿에서 해 볼 것
1. 빠르게 긴 획, 작은 글씨 쓰기: 지연과 끊김이 줄었는지.
2. 노트 밖 필기가 많은 노트에서 확대·축소한 뒤 바로 스크롤: 버벅임이 줄었는지.
3. 노트 밖에 계속 쓰기: 쓴 획이 바로 남고 버벅이지 않는지.
