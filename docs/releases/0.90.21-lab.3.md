## 부분 지우개 수정

- **도구에서 선택한 지우개도 펜 버튼 지우개와 같은 입력 우선순위를 사용**합니다. 선택된 필기 위에서 지우기를 시작할 때 선택 이동이 먼저 실행되던 경로를 수정했습니다. 캡처·이미지·도형 도구의 이전 상태가 지우기를 가로채지 않도록 했습니다. 버튼에 지정한 올가미·읽기 기능은 유지합니다.
- **점 사이의 선을 연속적으로 자릅니다.** 기존 방식은 점 두 개로 만든 긴 직선의 가운데만 지워도 선 전체를 없애거나, 점 사이의 작은 지우기 구간을 놓칠 수 있었습니다. 이제 지우개가 지나간 원형 영역과 선분이 만나는 위치를 계산해 양쪽 조각과 작은 남은 구간을 보존합니다. 필기 위에 처음 닿은 지점도 같은 계산을 사용합니다.
- 과거 입력 좌표까지 모아 **화면 프레임당 한 번 처리**합니다. 꺾인 경로를 대각선으로 생략하지 않고, 다음 프레임과의 연결도 유지합니다. 범위가 완전히 같은 일직선 이동만 합칩니다. 한 프레임 안에서 같은 원본 필기를 여러 번 잘라 다시 생성하는 작업을 줄였습니다.
- 조각 수가 같아도 변경된 프레임의 렌더 캐시를 무효화합니다. 펜을 떼기 전까지 이전 필기 모양이 남는 문제를 방지합니다. 공간 검색에서는 바뀌지 않은 필기의 경계와 셀 정보를 재사용합니다.
- 필기 조각을 원래 겹침 순서에 넣습니다. 되돌리기·다시 실행도 같은 순서를 복원합니다. 지우는 도중 생기는 중간 조각은 기록에 쌓지 않고, 제스처 전 원본과 마지막 조각만 보관합니다. 백그라운드 필기 재계산으로 객체가 바뀌는 경우에도 기록을 연결합니다.
- 펜을 떼거나 노트를 전환할 때 남은 지우기 입력을 반영합니다. 기존 필기 파일 형식과 레이어 잠금·활성 레이어·지울 대상 설정은 유지합니다.

## 성능 비교 방법과 결과

아래는 **로컬 빌드 호스트의 C++ 구간 계산만** 비교한 결과입니다. 각 행은 같은 원본 좌표에 네 번의 지우개 입력을 적용하는 묶음 2,000회입니다. 213의 판정을 네 번 호출하는 방식과 214에서 네 입력의 합집합을 한 번 계산하는 방식을 비교했습니다.

| 필기 점 수 | 213 계산 합계 | 214 계산 합계 | 계산 시간 감소 |
| --- | ---: | ---: | ---: |
| 64 | 32.23ms | 4.09ms | 87.3% |
| 512 | 297.03ms | 18.69ms | 93.7% |
| 4,096 | 2,382.16ms | 140.08ms | 94.1% |

**앱 전체 속도나 태블릿 프레임 개선율이 아닙니다.** JNI 전달, 필기 형상 생성, 캐시, 렌더링, 실기기 지연을 제외한 비교입니다. 이전 방식에서 조각이 매번 바뀌는 전체 파이프라인을 재현한 측정도 아닙니다. 새 계산은 선분 사이의 잘림까지 처리하므로 정확도도 달라졌습니다. 실행 환경에 따라 수치는 달라지며, CI 호스트의 별도 원시 결과는 릴리스에 첨부한 `Erase-host-comparison.txt`에서 확인할 수 있습니다.

## 진단 및 검증

- `partial erase work (frame)`: 프레임별 지우기 계산·반영 작업 시간입니다.
- `partial erase applied (not pixels)`: 해당 묶음의 가장 오래된 입력부터 필기 상태에 반영할 때까지입니다. 화면 픽셀이 바뀌는 시각은 측정하지 않습니다.
- 부분 지우개에서 `input handled`는 입력을 큐에 넣는 시간입니다. 이 숫자만 작아졌다고 지우기 전체가 빨라졌다고 해석하면 안 됩니다. 위 두 항목과 프레임 통계를 함께 비교해야 합니다.
- 연속 구간의 정확한 경계, 두 점 직선, 첫 접촉, 샘플 밀도, 역사 입력의 꺾임, 프레임 간 연결, 원래 겹침 순서와 되돌리기·다시 실행을 검사했습니다.
- 로컬 전체 Debug 테스트 **678개**가 실패·오류·건너뜀 없이 통과했습니다.
- 실제 호스트 JNI로 무작위 필기 500개를 Kotlin 결과와 비교하고, 별도의 점-선분 거리 판정 10,000개로 남아야 할 영역을 검증했습니다. C++ 메모리·정의되지 않은 동작 검사에는 1,000개 무작위 선과 잘못된 버퍼 용량 검사를 포함했습니다.
- 전체 단위 테스트, Android 네이티브 교차 빌드, 릴리스 APK 빌드, UI/JNI 검사와 기존 키 서명 검증을 통과한 뒤 사전 릴리스로 게시합니다.

태블릿의 체감 지우기 정확도·프레임·배터리·발열은 아직 실측하지 않았습니다. 같은 노트·확대율·지우개 크기·화면 주사율에서 213과 비교해 주세요. 특히 **선택된 필기 위에서 도구 지우개로 시작하기, 펜 버튼으로 같은 구간 지우기, 긴 직선의 가운데만 지우기, 빠르게 꺾어 지우기, 되돌리기·다시 실행**을 확인해 주세요.
