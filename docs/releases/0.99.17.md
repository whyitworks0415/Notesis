# Notesis 0.99.17 (258)

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

> ⚠️ 0.91.0부터 앱은 **Material 화면만** 씁니다. Liquid glass·Glassmorphism을 계속 쓰려면 0.90.28에 머무르세요.

## 사이드바가 모두 같은 모양으로 열립니다
- 설정, 페이지, Agent(에이전트에게 묻기), 레이어 패널은 지금까지 제각각 만들어져 있었습니다.
  - **설정:** 화면 오른쪽 끝에 붙어 위아래를 꽉 채웠습니다.
  - **페이지:** 가장자리에서 12dp 떨어져 떠 있었습니다.
  - **Agent:** 위아래에 8dp씩 틈이 있었고, 다른 애니메이션(밀기+흐려지기)으로 열렸습니다.
  - **레이어:** 화면 높이의 86%짜리 카드였습니다.
- 이제 네 패널이 모두 같은 틀을 씁니다.
  - 오른쪽 끝에 붙어 위아래를 채웁니다.
  - 위에 제목과 닫기 버튼이 있습니다.
  - 안쪽 가장자리의 손잡이로 폭을 바꿀 수 있습니다.
  - 모서리 모양과 열리는 애니메이션이 같습니다.
- 인터넷 AI 패널은 노트 옆에 붙어 노트를 좁히는 방식이라 그대로 두었습니다. 손잡이 폭만 다른 패널과 맞췄습니다.

## 팝업과 다이얼로그의 높이를 하나로 맞췄습니다
- **다이얼로그:** 내용 부분의 최대 높이가 420, 460, 520, 560, 600dp로 제각각이었습니다. 모두 520dp로 맞췄습니다.
- **툴바 팝업, 도구 패널, 메뉴:** 최대 높이가 각각 달랐습니다. 이제 모두 "화면 높이 − 140dp"까지 늘어납니다.
- 메뉴와 그 메뉴를 연 버튼 사이의 간격도 툴바 팝업과 같은 8dp로 맞췄습니다.

## 올가미로 옮길 때 붙는 기준이 늘었습니다 (Canva처럼)
- 지금까지는 쪽의 가장자리와 가운데, 그림의 가장자리에만 붙었습니다.
- 이제 다음 기준에도 붙습니다.
  - **쪽 여백**
  - **다른 필기:** 글자 하나하나가 아니라 단어나 줄 단위 덩어리의 가장자리와 가운데에 붙습니다.
  - **같은 간격:** 양옆 대상의 가운데에 오거나, 다른 두 대상 사이와 같은 간격이 되면 붙습니다. 맞춘 간격은 분홍 선으로 보여 줍니다.
- 올가미 막대의 **정렬 기준** 메뉴에서 기준을 하나씩 켜고 끌 수 있습니다.

## Ask agent: 실시간 진행, 대화 탭, 명령어
- **실시간 진행**
  - Agent가 생각하는 내용, 쓰는 답, 부르는 도구와 그 결과가 생기는 대로 대화창에 쌓입니다.
  - 답이 끝나면 진행 과정은 답 위에 "▸ N단계"로 접혀 남습니다. 사용한 토큰 수도 함께 보입니다.
- **대화 탭:** 대화마다 탭이 따로 있습니다. 각 탭은 Agent 쪽 대화 ID를 기억하므로 서로의 대화를 이어 쓰지 않습니다. 이전 버전은 "마지막 대화"를 이어 써서 다른 대화에 섞일 수 있었습니다.
- **명령어**
  - `/new` `/close` `/clear` `/agent codex` `/sessions` `/stop` `/help`: 대화창 자체 명령입니다.
  - 그 밖의 `/명령`: Agent의 자체 명령으로 그대로 전달합니다.
  - `!ls`: Debian에서 바로 실행하고, 출력이 나오는 대로 보여 줍니다.
  - `notesis list`: Agent를 거치지 않고 앱 안에서 바로 노트 명령을 실행합니다. 토큰을 쓰지 않습니다.
- **토큰 절약:** Claude Code는 원래 Notesis 도구만 허용되어 있습니다. 그런데도 요청할 때마다 쓰지도 못하는 자체 도구(파일, 셸, 웹) 설명이 함께 보내졌습니다. 지원하는 버전에서는 이제 보내지 않습니다.
- **긴 답 잘림:** 저장할 때 8,000자에서 잘라서, 앱을 다시 열면 긴 답의 끝이 사라졌습니다. 이제 잘리지 않습니다.
- 처음 요청할 때 앱이 Debian의 도우미 스크립트를 한 번 새로 고칩니다. 설정 스크립트를 다시 돌릴 필요는 없습니다.

## Agent가 노트에 쓴 글이 잘리던 문제
- 폭을 정하지 않고 쓴 글은 한 줄이 쪽보다 넓어져 오른쪽이 잘렸습니다. 긴 답은 쪽보다 길어 아래도 잘렸습니다.
- 이제 쪽 폭 안에서 줄을 바꾸고, 남은 공간보다 길면 바로 뒤에 새 쪽을 만들어 이어 씁니다. 나눌 때는 줄 사이에서 나누고, 줄 하나가 너무 길면 단어 사이에서 나눕니다.

## Markdown 노트에 필기 블록
- `/필기`(Handwriting)를 입력하면 문단 사이에 필기 칸이 생깁니다.
  - S펜으로 바로 쓸 수 있고, 손가락으로는 그대로 스크롤됩니다.
  - 펜의 지우개 끝이나 버튼으로 지울 수 있습니다.
- Obsidian의 그리기 플러그인처럼 두 파일로 저장합니다.
  - `![[ink-….png]]` 그림: 다른 Markdown 앱에서도 보입니다.
  - 옆에 두는 획 파일: Notesis가 다시 읽어 이어 쓸 때 씁니다.
- 필기에는 노트 쪽과 같은 저지연 잉크와 펜을 씁니다.

## 갑자기 전원이 꺼져도 필기가 남도록
- 쪽의 필기는 임시 파일에 다 쓴 다음, 이름을 바꿔 원래 파일을 대신하는 방식으로 저장합니다.
- 그런데 내용이 저장 장치에 실제로 기록됐는지 확인하지 않고 이름부터 바꿨습니다. 그래서 **배터리가 다 되거나 기기가 갑자기 재부팅되면** 그 쪽이 빈 쪽으로 열릴 수 있었습니다.
- 이제 기록을 확인한 뒤에 바꿉니다. 새 획만 덧붙일 때도 획을 먼저 기록하고, 그다음에 획 개수를 고쳐 씁니다.

## 개발 환경
- 빌드 설정 파일에 개발 PC의 Java 경로가 들어 있었습니다. 그래서 다른 컴퓨터에서 저장소를 받으면 빌드가 바로 실패했습니다.
- 이 경로를 PC 사용자 설정(`~/.gradle/gradle.properties`)으로 옮겼습니다.

## 어떻게 확인했나
- 릴리스 빌드, Lint, 전체 단위 테스트, 스크린샷 테스트를 돌렸습니다.
  - 네 사이드바를 같은 화면 크기로 찍어 모양이 같은지 확인했습니다.
- 새 테스트를 추가했습니다.
  - 글 나누기
  - 정렬 기준, 필기 덩어리, 같은 간격
  - 입력 구분(질문, 명령, 셸 줄, 노트 명령)
  - 대화 ID 읽기와 토큰 표시
  - 진행 중계 스크립트
  - 필기 블록 이름과 `/필기`
- 새 도우미 스크립트는 가짜 Agent로 PC에서 돌려 확인했습니다. 입력한 문장은 Agent에 하나의 인자로만 전달되고 명령으로 실행되지 않으며, 대화 ID가 돌아오는 것까지 확인했습니다.

## 하지 않은 것 / 확인하지 못한 것
- 이번에는 **태블릿이 연결되어 있지 않았습니다.** 아래는 기기에서 시험하지 못했습니다.
  - 사이드바 애니메이션
  - Markdown 필기 블록의 필기감
  - Agent 실시간 진행
- 필기 속도와 인터넷 AI 창 속도는 측정할 근거가 없어 바꾸지 않았습니다. 무엇이 느린지 알려 주시면 그 부분을 재서 고치겠습니다.
- Claude Code의 진행 표시는 이벤트 단위로 읽습니다. Codex, Gemini, OpenCode는 출력 줄 단위로만 보입니다.
- Markdown 필기 블록은 높이가 정해져 있고, 늘리는 기능은 아직 없습니다.
- 실제로 전원을 끊어 보는 시험은 하지 않았습니다.

## 태블릿에서 해 볼 것
1. 설정, 페이지, Agent, 레이어를 차례로 열어 보기 → 모두 같은 자리에서 같은 모양으로 열리는지.
2. 올가미로 필기를 옮기기 → 다른 필기 줄이나 여백에 붙는지, **정렬 기준** 메뉴에서 끄면 안 붙는지.
3. Ask agent에서 질문하기 → 생각과 도구 호출이 바로 보이는지. 새 탭(`/new`)을 열어도 앞 대화와 섞이지 않는지.
4. Ask agent에 `notesis list`와 `!ls` 입력하기.
5. Markdown 노트에서 `/필기` → 펜으로 쓰고, 노트를 닫았다 다시 열어도 남아 있는지.
6. Agent에게 긴 글을 노트에 쓰게 하기 → 오른쪽과 아래가 잘리지 않는지.
