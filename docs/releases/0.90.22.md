# Notesis 0.90.22 (222)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

## 바뀐 점

### 1. 첫 화면 스크롤
- 0.90.21에서 노트·폴더 카드마다 붙였던 오프스크린 레이어를 뺐습니다. 카드가 화면에 들어올 때마다 카드 크기의 텍스처를 새로 잡고 채워야 해서, 새 줄이 나타날 때 멈칫하는 원인이 될 수 있었습니다. 카드 모양, 테두리, 썸네일은 그대로입니다.
- 스크롤을 시작할 때 상단 헤더를 레이어로 바꾸던 처리도 뺐습니다. 스크롤마다 첫 프레임에 헤더 크기의 텍스처를 만들었기 때문입니다. 헤더 유리가 보는 배경은 원래처럼 스크롤 중에는 고정됩니다.
- Glassmorphism 외관의 서리 배경도 스크롤 중에는 다시 기록하지 않습니다. 지금까지는 스크롤하는 동안 매 프레임 라이브러리 전체를 다시 기록했고, 그 위의 패널도 매번 다시 흐려졌습니다.

### 2. 사이드바·페이지 패널·레이어 패널 열림
- 이 패널들은 레이어 위치를 옮겨 미끄러지게 했습니다. 그런데 Kyant 유리는 화면 위치가 바뀌면 다시 그려지기 때문에, 열리고 닫히는 동안 매 프레임 배경을 다시 흐리게 했습니다. 버벅임의 원인입니다.
- 이제는 그리기 단계에서만 옮깁니다. 패널은 처음부터 멈출 자리에 배치되어 있고, 유리는 그 자리의 배경을 한 번만 흐려 그림처럼 함께 들어옵니다. 사이드바 안 내용이 조금 늦게 따라 들어오는 움직임도 같은 방식으로 바꿨습니다.
- 스프링, 시간, 끝을 당기는 동작은 바꾸지 않았습니다.

### 3. 팝업의 등장과 사라짐 — Mornye의 메뉴를 따름
Mornye 재생 화면의 가로 점 3개 메뉴 코드를 읽고 값을 옮겼습니다(코드는 복사하지 않았습니다).
- **등장**: 버튼 자리의 44pt 둥근 방울에서 시작합니다. 세로가 먼저 흘러내리고 가로는 50ms 늦게 퍼집니다. 스프링은 Mornye와 같은 감쇠비 0.62, 15 rad/s이고, 기본 모션 속도(1.3배)에서는 약 19 rad/s입니다. 크기를 넘어서는 부분은 35%만 남겨 작게 흔들린 뒤 멈춥니다. 모서리는 방울일 때 완전히 둥글다가 퍼지면서 패널 모서리로 바뀝니다.
- **내용**: 글자와 버튼은 커지거나 찌그러지지 않습니다. 멈출 자리에 그대로 있고, 유리가 닿은 곳만 보입니다. 방울이 반쯤 내려왔을 때부터 서서히 나타납니다. 0.90.21에서는 창 전체를 확대해서 글자도 함께 늘어났는데, 이것이 "모션이 달라졌다"는 부분으로 보입니다.
- **사라짐**: 240ms 동안 버튼으로 돌아갑니다. 가로가 먼저(200ms) 접히고, 내용은 유리가 줄기 전에 먼저 사라집니다.
- 외곽선은 둥근 사각형이라 렌더 스레드가 직접 자릅니다. 움직이는 동안 패널은 한 번만 기록하고, 프레임마다 외곽선만 바꿉니다.
- 적용 대상: 툴바 메뉴, 도구 패널(펜 설정 등), 공통 메뉴, 확인창. 확인창은 내용 페이드 없이 방울 모양만 적용됩니다.

### 4. 끝 드래그 — 목록 끝 반동
- 첫 화면 목록, 팝업 메뉴, 도구 패널에서 끝을 넘어 당기면 iOS나 Mornye처럼 점점 덜 따라오다가 놓으면 제자리로 돌아갑니다. 빠르게 넘기다 끝에 닿으면 조금(최대 72dp) 넘어갔다가 돌아옵니다.
- 목록이 쓰고 남은 이동량만 받아서, 평소 스크롤은 바뀌지 않습니다. 시스템 애니메이션이 꺼져 있거나 고대비 모드일 때는 기존 안드로이드 늘어남 효과를 씁니다.
- 반동하는 동안에도 첫 화면 배경 기록은 멈춰 있습니다.

## 확인 방법

- 로컬: 방울 모양(시작 크기, 버튼 위치, 패널 안에 머무름, 세로가 먼저 내려옴, 모서리, 넘침 35%)과 내용 투명도, 끝 반동 계산(당김과 표시 거리의 역변환, 최대 넘침)을 JVM 단위 테스트로 확인했습니다(8개 통과).
- CI check 빌드: 릴리스 빌드, 전체 단위 테스트, UI 테스트. 팝업이 열리는 중에도 버튼이 제자리에 있고 탭이 한 번만 들어가는지 보는 UI 테스트를 새 동작에 맞게 바꿨습니다. 실제 결과는 Actions 실행 기록에서 확인해 주세요.
- 헤더 레이어를 뺐기 때문에 그 레이어를 확인하던 화면 테스트도 지웠습니다.

## 하지 않은 것 / 모르는 것

- **기기에서는 시험하지 않았습니다.** 프레임 수나 지연을 재지 않았으므로 얼마나 부드러워졌는지는 모릅니다.
- 끝 반동은 Compose 기본 스크롤 위에 직접 만든 것입니다. 다른 목록(설정 페이지, 노트 안 패널 등)에는 아직 넣지 않았습니다.
- 패널이 미끄러지는 동안 터치는 패널이 멈출 자리 기준으로 들어갑니다. 열리거나 닫히는 0.3초 정도에만 해당합니다.
- 노트 화면 스크롤과 펜 경로는 바꾸지 않았습니다.

## 태블릿에서 해 볼 것

1. 노트가 많은 첫 화면에서 천천히·빠르게 위아래로 스크롤하고, 새 줄이 나타날 때 멈칫하는지 봅니다. 맨 위·맨 아래에서 더 당겨 보고 빠르게 넘겨 끝에 부딪혀 봅니다.
2. 툴바 메뉴와 펜 설정을 열고 닫아 봅니다. 방울에서 퍼지는 모양, 흔들림, 글자가 늘어나지 않는지, 닫힐 때 가로가 먼저 접히는지 봅니다.
3. 설정 사이드바, 페이지 패널, 레이어 패널을 여러 번 열고 닫으며 버벅임을 봅니다. iOS·Mornye 외관과 60Hz 화면에서 각각 해 봅니다.
4. 설정 → 모션 속도를 바꾼 뒤 2와 3을 다시 해 봅니다.
