# Notesis Lab 0.90.21-lab.4 (215)

<!-- update: manual -->

> 수동 성능 실험판입니다. 기존 **Notesis Lab**의 업데이트이며 정식 Notesis와는 별도입니다. **About · Help → Check for updates** 또는 APK 링크로 설치할 수 있습니다.

## 이번 빌드의 목적

펜으로 쓸 때 시간이 어디서 쓰이는지 **재고**, 쓰기 지연을 줄일 수 있는 두 가지를 **스위치로 켜고 끄며 비교**할 수 있게 한 빌드입니다. 지연이 줄었는지는 아직 아무도 재지 않았습니다. 태블릿에서 같은 글씨를 써 보며 스위치를 하나씩 바꿔 비교해 주세요.

설정 → **Diagnostics**(Lab 설치에서는 항상 보입니다) → **Write path (Lab)**에 스위치가 있습니다.

## 바뀐 점

### 1. 쓰기 경로 계측
- 단계별 시간(형상 생성, 서피스 버퍼 대기, 그리기와 제출, 입력 처리, 쓰는 중 잉크)은 이미 진단 화면에 있었습니다. 이번에 다음을 더했습니다.
  - **Pressure rewrite (per pen event)**: 필압을 끄거나 곡선을 적용한 펜이 샘플마다 이벤트를 복사하는 데 드는 시간입니다. 0.90.20에서 필압 스위치가 모든 펜에 듣도록 하면서 이 복사가 늘었는데, 그 비용을 처음으로 잴 수 있습니다.
  - **Performance hint status**와 **Own buffers status**: 아래 두 실험이 지금 켜져 있는지, 시스템이 받아들였는지, 실패해서 돌아갔는지 보여 줍니다.
- 지연 오버레이를 켜야 숫자가 모입니다. 끄면 측정 비용이 없습니다.

### 2. 쓰는 동안 성능 힌트 (기본 켜짐)
- 펜이 호버하거나 닿아 있는 동안, 펜을 위해 일하는 스레드(UI 스레드, 잉크 표시 스레드)를 시스템에 알립니다(Android 12 이상의 `PerformanceHintManager`). 일이 시작되기 전에 CPU 속도를 올릴 수 있게 하려는 것입니다.
- 세션은 **호버가 시작될 때** 엽니다. 세션을 여는 것이 다른 프로세스로의 호출이라 첫 잉크가 그것을 기다리지 않게 하기 위해서입니다. 펜이 떠난 뒤 2.5초 뒤에 닫아서 단어 사이의 쉬는 시간에 닫혔다 열리지 않습니다.
- 목표 시간은 화면 한 프레임의 40%로 정했습니다. **이 값은 추측**이고, 시간이 지나치게 낮게 보고되면 오히려 CPU를 내릴 수 있어서 비교가 필요합니다. 스위치를 끄면 사용하지 않습니다.
- 효과가 있는지는 모릅니다.

### 3. 쓰는 중인 잉크를 앱이 가진 버퍼로 표시 (실험, 기본 꺼짐)
- 지금까지는 서피스의 캔버스를 잠글 때 디스플레이가 버퍼를 돌려줄 때까지 기다렸고, S6 Lite에서는 그것이 대부분 한 프레임이었다고 코드에 적혀 있습니다.
- 이 실험은 하드웨어 버퍼 3개를 미리 만들어 두고, 한 프레임을 그중 컴포지터가 놓은 버퍼에 쓴 뒤 서피스 트랜잭션으로 화면에 바로 넘깁니다. 디스플레이를 기다리지 않습니다. 돌아온 버퍼는 다음에 그 버퍼가 필요할 때만 기다립니다.
- C++(`present_jni.cpp`)로 만들었고 Android 10 이상에서만 동작합니다.
- 하나라도 실패하면(라이브러리 로드, 버퍼 할당, 서피스 컨트롤, 복사) 스스로 원래 방식으로 돌아가고, **Own buffers status**에 실패했다고 나옵니다.
- **노트를 새로 열 때부터** 적용됩니다.
- 이 경로는 **기기 없이 만들었습니다.** 호스트 컴파일러로 문법 검사만 했고 Android에서는 실행해 보지 못했습니다. 쓰는 동안 깜빡이거나 사라지거나 늦게 따라오면 알려 주세요. 스위치를 끄면 원래 경로입니다.
- 버퍼 3개는 화면 크기만큼 메모리를 더 씁니다.

## 확인한 것 / 하지 않은 것

- 확인한 것: CI의 네이티브 검사, 단위 테스트, 릴리스 빌드(최종 Actions 실행에 기록). 새 테스트는 힌트 목표 시간의 범위, 스위치의 기본값, 상태 이름, 새 계측 항목을 확인합니다.
- **기기에서는 확인하지 못했습니다.** 쓰기 지연이 줄었는지, 늘었는지 아직 모릅니다.
- 새 C++ 코드의 버퍼 순환(어느 버퍼가 비었는지, 다시 그릴 영역을 어떻게 추적하는지)은 단위 테스트가 없습니다. Android 헤더가 필요해서 호스트에서 돌릴 수 없습니다.
- 펜 이동 경로의 할당을 훑어보았지만 전부 읽은 것은 아닙니다. 새로 찾은 문제는 없습니다.
- 0.90.20에서 필압을 끈 펜이 모든 샘플을 복사하게 한 것은 이번에 바꾸지 않았습니다. 위 계측 숫자를 보고 정합니다.

## 비교해 볼 것

1. 지연 오버레이를 켜고, 같은 노트·같은 펜·같은 설정으로 같은 문장을 여러 줄 씁니다. **Compatible ink: waiting for the surface**, **Wet ink**, **Input handled**의 p50 · p95 · p99를 적어 둡니다.
2. **성능 힌트**를 껐다 켜며 1을 반복합니다. 한 번에 하나만 바꿉니다.
3. **자체 버퍼 표시**를 켜고 노트를 다시 열어 1을 반복합니다. 이때 **쓰는 동안 깜빡임, 잔상, 획이 늦게 사라짐, 지우개 커서**를 눈으로도 확인합니다.
4. 필압을 끈 만년필로 쓸 때 **Pressure rewrite** 숫자를 적어 둡니다.
5. 10분 이상 쓴 뒤의 발열과 배터리는 따로 확인합니다.
