# Notesis 0.99.16 (257)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

> ⚠️ 0.91.0부터 앱은 **Material 화면만** 씁니다. Liquid glass·Glassmorphism을 계속 쓰려면 0.90.28에 머무르세요.

이번 버전은 처음으로 **태블릿(Galaxy Tab S8 Ultra, Android 16, 120Hz)에 연결해서 직접 측정하며** 고쳤습니다. 가상 S펜과 가상 터치를 기기 입력 경로에 넣어 같은 필기·스크롤·핀치를 반복하고, 수정 전과 후를 같은 조건으로 비교했습니다.

## 필기: 쓰는 동안 화면 전체를 다시 그리던 문제
- 모션 블러의 **"필기"** 항목이 기본으로 켜져 있어서, 펜 끝 앞의 잔상이 펜이 움직일 때마다 화면 전체를 다시 그리게 했습니다.
  - 필기는 원래 front buffer가 직접 그리므로, 쓰는 동안 앱 화면은 다시 그릴 필요가 없습니다.
- 이 태블릿에서는 화면을 다시 그릴 때마다 시스템이 주사율 기록을 위해 스택 추적과 로그를 남깁니다. 그 비용이 컸습니다.
- 이제 이 잔상은 **60Hz 화면에서만** 그립니다. 설정 설명대로, 초당 60프레임만 보여 주는 화면에서 끊김을 가리기 위한 기능입니다.
  - 120Hz에서는 프레임 사이 이동이 짧아서 잔상이 거의 보이지 않았습니다.
  - 펜마다 직접 고른 "모션 블러"나 "잔상(Trail)"은 그대로 그립니다.
- 같은 필기 재현(10줄)에서 잰 값:

  | | 수정 전 | 수정 후 |
  |---|---|---|
  | 앱이 그린 프레임 | 2,144개 (초당 약 107개) | 85개 (획을 마칠 때만) |
  | UI 스레드의 화면 그리기 | 초당 약 91ms | 초당 약 5ms |
  | 시스템 주사율 기록 비용 | 초당 약 58ms | 초당 약 3ms |

## "라이트 모드를 켤까요?"가 빠른 태블릿에서도 뜨던 문제
- 288쪽 PDF를 열자마자 S8 Ultra에서도 *"이 태블릿이 프레임을 놓치고 있습니다"* 창이 떴습니다.
- 원인은 판정 기준이었습니다. 프레임의 **전체 시간**은 GPU가 앞 프레임들을 끝낼 때까지 기다린 시간까지 포함합니다. 120Hz에서는 그 대기만으로도 기준(2프레임)을 넘습니다.
  - 실제로 끊긴 프레임은 3% 남짓이었는데, 거의 모든 프레임이 늦은 것으로 셌습니다.
- 이제 프레임이 **실제로 일한 시간**(앱이 그리는 단계들의 합, 또는 GPU 시간 중 긴 쪽)으로 판정합니다.

## 핀치로 확대·축소한 뒤 쪽이 옆으로 미끄러지던 문제
- 두 손가락을 떼는 순간, 마지막 손가락의 속도로 쪽이 던져졌습니다.
  - 핀치를 마칠 때는 확대 인식이 이미 끝난 뒤라서, "핀치 중에는 던지지 않음" 검사를 그냥 지나쳤습니다.
- 태블릿에서 화면 가운데를 기준으로 축소했을 때, 쪽이 오른쪽으로 약 380px 밀려났습니다.
- 이제 손이 닿아 있는 동안 배율이 1% 넘게 바뀌었으면 손을 떼도 던지지 않습니다. 두 손가락으로 **옮기기만** 한 경우의 플링은 그대로입니다.
- 같은 핀치 재현에서 쪽이 화면 가운데에 그대로 남는 것을 확인했습니다.

## 시계 버튼이 백업 버튼을 가리던 문제
- 처음 설치하면 시계 버튼이 오른쪽 아래(90% 높이)에 있었습니다. 홈 화면에서는 백업 버튼 위에 겹쳐 백업 버튼이 거의 가려졌습니다.
- 처음 위치를 **오른쪽 위**(제목 줄 아래)로 바꿨습니다. 이미 옮겨 둔 시계는 그 자리에 그대로 있습니다.

## 가져온 PDF 제목
- 다른 앱에서 **"열기"로 가져온 PDF는 제목에 `.pdf`가 남았습니다.** 앱 안에서 골라 가져온 PDF는 `.pdf`를 떼는 것과 달랐습니다. 이제 두 경로 모두 같은 규칙으로 제목을 만듭니다.
- 한국어 파일 이름이 다른 인코딩으로 잘못 읽혀 `2026ÇÐ³âµµ…`처럼 보이던 이름을 `2026학년도…`로 되돌립니다.
  - CP949로 쓴 이름과 UTF-8로 쓴 이름 둘 다 해당합니다.
  - 되돌린 결과에 한글이 있을 때만 바꿔서, `Café` 같은 원래 이름은 건드리지 않습니다.
  - 이미 만들어진 노트의 제목은 바꾸지 않습니다. 새로 가져올 때부터 적용됩니다.

## 측정했지만 넣지 않은 것
- **PDF 페이지 그림을 백그라운드에서 GPU로 올리는 변경**을 시험했습니다.
  - 느린 비트맵 업로드는 두 번 모두 2회에서 0회가 됐습니다.
  - 하지만 그 그림을 처음 그릴 때 렌더 스레드가 GPU 버퍼를 가져오는 비용(약 8ms)이 새로 생겨, 가장 느린 1% 프레임이 11~12ms에서 17ms로 나빠졌습니다.
  - 이득이 아니어서 되돌렸습니다.
- **지우개, 노트 열기, 앱 실행**은 측정만 하고 바꾸지 않았습니다.
  - 지우개: 빽빽한 필기 위에서 UI 스레드 p99 4.5ms
  - 앱 실행: 289ms
  - 288쪽 노트 열기: 느린 프레임 3개
- **Compose 화면에 남은 비용**이 하나 있습니다. Compose(1.11)는 Android 15 이상에서 다시 그릴 때마다 주사율을 기록하고, 이 태블릿에서는 그때마다 스택 추적이 일어납니다(프레임당 약 0.5ms). 라이브러리 안의 동작이라 이번에는 바꾸지 않았습니다.

## 어떻게 확인했나
- 태블릿에 측정용 빌드(`com.notesis.bench`, 원래 앱과 따로 설치되는 최적화 빌드)를 설치했습니다. 실제 노트는 건드리지 않았습니다.
- 시스템 `uinput`으로 등록한 가상 S펜·터치로 필기, 스크롤, 핀치를 재현했습니다.
- `gfxinfo` 프레임 통계와 `simpleperf` UI 스레드 프로파일로 수정 전후를 비교했습니다. 재현 스크립트는 `tools/performance-lab/device_replay.py`에 남겼습니다.
- 축소(R8) 릴리스 빌드, Lint, 전체 단위 테스트를 돌렸습니다.
  - 새 테스트: 제목 정리, 프레임 판정, 핀치 후 플링, 120Hz 잔상
- 네이티브 커널 점검(`check-native.sh`)은 이 PC에 Linux 컴파일러가 없어 돌리지 못했습니다. 네이티브 코드는 바꾸지 않았습니다.

## 하지 않은 것 / 확인하지 못한 것
- 측정은 가상 입력으로 했습니다. **실제 S펜으로 쓸 때의 감각**(지연, 잔상이 없어진 느낌)은 직접 써 보셔야 합니다.
- 정식 앱(`com.notesis`)에 실제 노트가 많은 상태에서는 측정하지 않았습니다.
- 60Hz 태블릿(S6 Lite)에서는 잔상이 그대로이므로 동작이 바뀌지 않습니다. 그 기기에서는 시험하지 못했습니다.

## 태블릿에서 해 볼 것
1. 노트에 빠르게 길게 써 보기 → 펜 끝 앞의 옅은 잔상이 없고, 쓰는 느낌이 그대로이거나 더 가벼운지.
2. 두 손가락으로 축소·확대한 뒤 손을 떼기 → 쪽이 옆으로 미끄러지지 않는지. 두 손가락으로 쓸어 넘기면 여전히 미끄러져 가는지.
3. 홈 화면 오른쪽 아래 → 백업 버튼이 시계에 가리지 않는지. (이미 시계를 옮기셨다면 그 자리 그대로입니다.)
4. 다른 앱에서 PDF를 "Notesis로 열기" → 제목에 `.pdf`가 붙지 않고, 한글 이름이 깨지지 않는지.
