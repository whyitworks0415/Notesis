# Notesis 0.90.12 (203)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다. 개발자 코드를 넣은 베타 테스터에게만 보입니다.

## 바뀐 점: Apple식 모션과 60Hz 부드러움

### 스프링으로 움직이기
- 앱의 기본 움직임(`Ui.Motion`)을 고정 시간 곡선(180ms)에서 **스프링**으로 바꿨습니다.
  - 넘치지 않는 스프링이고, 응답 시간은 0.3초입니다.
  - 그래서 페이드, 슬라이드, 크로스페이드, 튜토리얼 등이 도중에 방향이 바뀌어도 속도를 이어받습니다.
  - 순서대로 나타나는 목록처럼 지연이 있는 움직임은 곡선 그대로 둡니다. 스프링은 기다릴 수 없기 때문입니다.
- **설정 사이드바**: 들어올 때는 넘치지 않는 느린 스프링을 씁니다. 나갈 때는 조금 더 빠른 스프링입니다.
- **스프링 토큰**: SwiftUI 방식(강성 = (2π/응답)²)으로 네 가지를 정했습니다.
  - 빠른 이동: 0.25s / 0.85
  - 보통 이동: 0.36s / 0.86
  - 느린 이동: 0.46s / 1.0
  - 색·투명도: 0.22s / 1.0

### 도중에 끊고 되돌리기
- **팝업과 메뉴**: 열리는 도중에 닫으면 지금 위치와 속도에서 바로 되돌아갑니다. 예전에는 정해진 속도로 던지듯 닫혔습니다.
  - 닫히는 도중에 다시 열어도 그 자리에서 이어서 열립니다. 쏟아지는 열림의 50ms 지연도 다시 기다리지 않습니다.
- **다이얼로그**: 바깥을 누르거나 뒤로 가기로 닫으면 160ms 동안 줄어들며 사라집니다.
  - 다이얼로그 안의 버튼으로 닫을 때는 지금처럼 바로 닫힙니다.

### 손의 속도 이어받기와 고무줄 효과
- **분할 화면 분할선**:
  - 손을 뗄 때의 속도로 "던진 경우 멈출 위치"를 계산해서, 가장자리 쪽으로 툭 튕기기만 해도 그 칸이 닫힙니다.
  - 분할선이 손가락보다 한 프레임 앞서 그려져서(최대 16dp) 끌려오는 느낌이 줄어듭니다.
  - 소수점 픽셀 위치로 움직입니다.
- **설정 사이드바 너비**: 가장 넓은 너비를 넘겨 당기면 iOS 고무줄 공식(c = 0.55)으로 점점 뻑뻑해지고, 놓으면 가장 넓은 너비로 돌아옵니다.

### 햅틱 (약하게, 끌 수 있음)
- **울리는 곳**:
  - 스위치를 켜고 끌 때
  - 눈금이 있는 슬라이더가 다음 눈금에 닿을 때
  - 세그먼트를 바꿀 때
  - 분할선을 끌다가 "놓으면 닫힘" 지점에 들어설 때
  - 사이드바 너비가 한계에 닿거나 닫힘 지점을 넘을 때
- **강도**: 가장 약한 "틱"(CLOCK_TICK, Android 14 이상은 SEGMENT_TICK)만 씁니다.
- **끄기**: **설정 › 모양 › 모션 › 햅틱**에서 끌 수 있습니다. 태블릿 자체의 진동 설정도 그대로 적용됩니다.

### 60Hz에서 부드럽게
- **움직이는 동안 배경 기록 멈춤**
  - 팝업이나 사이드바가 움직이는 동안에는 유리 뒤 페이지를 매 프레임 다시 기록하지 않습니다. 홈과 노트 화면 모두 해당합니다.
  - 그동안 뒤 페이지는 바뀌지 않으므로 마지막 장면을 다시 씁니다.
  - 예전에는 이 기록이 움직이는 프레임마다 가장 무거운 일이었습니다.
- **유리 미리 준비**: 앱이 뜨고 1.2초 뒤, 필기나 이동이 없을 때 보이지 않는 작은 유리를 3프레임 그려서 셰이더와 블러를 미리 준비합니다. Mornye의 방식과 같습니다.
- **소수점 위치**: 도구 막대의 선택 표시와 분할선을 정수 픽셀이 아니라 소수점 위치로 그려서, 느린 꼬리에서 계단처럼 움직이지 않게 했습니다.
- **60Hz 보정**: 화면이 75Hz 이하이면 스프링을 12% 길게 써서 프레임당 이동 폭을 줄입니다. 120Hz 기기에서는 그대로입니다.
- **모션 블러**: 60Hz 화면에서 팝업이 가장 빠르게 움직이는 순간에만, 프레임 간 이동의 1/5만큼(최대 4dp) 블러를 넣습니다.
  - 가벼운 모드에서는 꺼지고, 설정에서 끌 수 있습니다.
- **측정**: **설정 › 모양 › 모션** 아래에 "화면 요소가 움직이는 동안"의 프레임 수, 늦은 프레임 수(1.5프레임 초과), 가장 긴 프레임을 보여 줍니다. 초기화도 할 수 있습니다.

### 모션 속도
- 기본은 100%로, 맞춰 둔 값 그대로입니다. 60Hz 보정은 이와 별도로 자동 적용됩니다.
- **설정 › 모양 › 모션 › 속도**에서 70~140%로 바꿀 수 있습니다.

## 확인한 것
- CI에서 빌드, 단위 테스트, 스크린샷 테스트를 돌렸습니다.
- 새 단위 테스트(`MotionTest`)로 다음 계산을 확인합니다.
  - 스프링 강성, 60Hz 보정
  - 던짐 예상 위치, 고무줄 함수, 손가락 앞섬, 모션 블러 크기
  - 기본 움직임이 스프링인지, 속도·60Hz 보정이 스프링과 곡선에 적용되는지
- **기기(태블릿)에서는 시험하지 못했습니다.**
  - 부드러움, 햅틱 세기, 모션 블러 비용은 보지 못했고 측정하지도 않았습니다.
  - 위 측정 화면의 숫자로 기기에서 확인해 주세요.

## 하지 않은 것
- **실제 크기로 쏟아지는 메뉴**: 쏟아지는 메뉴는 아직 배율로 움직입니다. 그래서 퍼지는 동안 스쿼클 모서리가 살짝 타원으로 눌립니다. 레이아웃을 바꾸는 큰 작업이라 기기 확인 없이 넣지 않았습니다.
- **노트 열기 전환**: 홈 카드에서 페이지로 커지는 전환은 넣지 않았습니다.
- **도구 막대 크기 전환**: 사용자가 정한 시간과 곡선을 따르는 설정이 따로 있어서 스프링으로 바꾸지 않았습니다.
- **햅틱 범위**: 도구 막대에서 도구를 고를 때는 햅틱을 넣지 않았습니다. 필기 중에 너무 자주 울릴 수 있어서입니다.
- **다이얼로그 버튼**: 다이얼로그 안의 버튼으로 닫을 때는 애니메이션이 없습니다.
- **프레임 시간 기준**: Compose 애니메이션과 캔버스 관성 스크롤은 이미 화면에 나갈 시각(vsync 프레임 시간) 기준이라 그대로 두었습니다.

## 태블릿에서 해볼 것
1. Functions 메뉴와 펜 패널을 열다가 바로 닫아 보고, 닫다가 다시 열어 봅니다. 끊기지 않고 이어지는지 봅니다.
2. 설정 사이드바를 열고 닫아 봅니다. 너비 조절 손잡이를 최대 너비 너머로 당겨 고무줄처럼 버티는지 봅니다.
3. 분할 화면에서 분할선을 가장자리 쪽으로 툭 튕겨 봅니다. 닫히는지, "놓으면 닫힘"에 들어설 때 톡 울리는지 봅니다.
4. 스위치, 슬라이더, 세그먼트를 조작하며 햅틱이 너무 세지 않은지 봅니다. 설정 › 모양 › 모션에서 꺼 봅니다.
5. 설정 › 모양 › 모션의 "늦은 프레임"을 초기화한 뒤 메뉴를 여러 번 열고 닫아 보고, 숫자를 알려 주세요.
6. 모션 블러를 껐다 켜며 차이를 봅니다.
