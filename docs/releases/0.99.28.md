# Notesis 0.99.28 (269)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

## 필기가 끊겨 그려지던 문제
쓰는 동안 필기가 매끄럽게 이어지지 않고, 몇 조각씩 끊겨 나타나는 것처럼 보였습니다. Material에서도 같았습니다.

### 원인으로 본 것
- 120Hz 태블릿에서 쓰는 중인 필기는 **front buffer**(화면에 바로 쓰는 버퍼)가 그립니다. 앱 화면 자체는 다시 그리지 않습니다.
- 0.99.16에서 비용을 줄이려고, 120Hz 화면에서는 쓰는 동안 앱 화면을 매 프레임 다시 그리던 동작(필기 잔상)을 껐습니다. 그 뒤로 펜이 움직이는 동안 앱이 새 프레임을 하나도 내지 않게 되었습니다.
- 새 프레임이 없으면 태블릿이 화면 주사율을 스스로 낮출 수 있습니다. 그러면 front buffer의 필기가 화면에 반영되는 간격이 길어져, 필기가 조각조각 나타납니다.

### 바뀐 점
- 쓰는 동안(펜이 닿아 있는 동안)에만, 화면 구석 **1픽셀**(사실상 투명)을 매 프레임 바꿔 앱이 계속 프레임을 내게 했습니다. 이 1픽셀 외에는 아무것도 다시 그리지 않습니다.
  - 0.99.16 이전처럼 화면 전체(잔상, 툴바, 패널)를 다시 그리지 않으므로, 그때보다 가볍습니다.
- Android 15 이상에서는 이 1픽셀이 가장 높은 주사율을 요청합니다.
- 펜을 떼면 바로 멈춥니다. 지우개, 올가미, 손가락 스크롤에는 쓰지 않습니다.
- 호환 경로(S6 Lite 등)와 필기 잔상이 켜진 60Hz 화면은 원래 매 프레임 그리므로 이 동작을 쓰지 않습니다.

## iOS 라이트 삭제
- 0.99.27의 "iOS 라이트" 스타일을 지웠습니다.
- 이 스타일을 고른 상태였다면 기본 Liquid glass로 돌아갑니다.
- iOS와 Liquid glass는 그대로입니다.

## 어떻게 확인했나
- 빌드, 축소(R8) 릴리스 빌드, Android 버전 검사(Lint), 네이티브 커널 점검, 전체 단위 테스트(155개 클래스)를 통과했습니다.
- 언제 이 동작을 쓰는지 정하는 조건에 테스트를 추가했습니다.

## 하지 않은 것 / 확인하지 못한 것
- **태블릿에서 직접 써 보지 않았습니다.** 원인을 측정으로 확인한 것이 아니라 코드와 0.99.16의 변경 내용으로 추정한 것입니다.
- 그래도 끊겨 보이면 펜 설정의 **잉크 경로**를 "호환(compat)"으로 바꿔 보세요. 그쪽은 매 프레임 직접 그립니다. 그때 어떻게 보였는지 알려 주시면 다음에 반영하겠습니다.

## 태블릿에서 해 볼 것
1. Material에서 빠르게 긴 획과 작은 글씨를 써 보기: 필기가 끊기지 않고 이어서 나타나는지.
2. 유리 스타일에서도 같은지.
3. 쓰는 동안 툴바나 다른 화면이 버벅이지 않는지.
