# Notesis 0.90.28 (228)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

통합 진단 문서(과제 K01~K45)를 따라 만든 첫 번째 묶음입니다. 기기 없이 확실하게 만들 수 있는 것만 넣었고, 나머지는 아래 "하지 않은 것"에 적었습니다.

## 바뀐 점

### 1. Android 10에서 앱이 꺼지던 문제 (K01)
- 화면 주사율을 읽는 코드 세 곳이 Android 11부터 있는 기능을 버전 확인 없이 쓰고 있었습니다. 그중 한 곳은 **앱이 화면에 나올 때마다** 실행돼서, Android 10에서는 앱을 열자마자 꺼질 수 있었습니다. 나머지 둘은 모션 설정 화면과 프레임 감시였습니다.
- 세 곳 모두 버전에 맞는 방법으로 읽도록 한 군데로 모았습니다.

### 2. 펜이 안 써지거나 획이 사라지는 문제 (K03)
- 펜 설정의 스위치 두 개(호환 잉크, 화면과 함께 그리기)를 **쓰는 중인 획을 보여 주는 방식** 하나로 합쳤습니다. 자동 / 가장 빠름 / 호환 / 가장 안전 중에서 고릅니다.
- **자동**은 Android 13보다 낮은 기기에서 '가장 안전'을 씁니다. 획을 화면의 나머지와 함께 그리는 가장 단순한 방식이라 가장 확실하게 보입니다. Android 13 이상은 지금처럼 '가장 빠름', S6 Lite는 지금처럼 '호환'입니다.
- 설정 아래에 지금 실제로 쓰는 방식과 그 이유가 나옵니다.
- 예전에 스위치를 직접 바꿔 둔 기기는 그 선택을 그대로 이어받습니다.

### 3. 절전·발열 때 꾸밈 효과 끄기 (K05, K17, K22, K27)
- 모션 블러가 가벼운 모드에서만 꺼지고 **시스템 절전 모드와 발열 상태에서는 그대로 그려지던 것**을 고쳤습니다.
- 기기가 뜨거워지면 단계적으로 낮춥니다.
  - 1단계(따뜻함): 모션 블러 끔, 유리를 한 번만 계산하는 가벼운 방식으로, 손글씨 인식 미룸
  - 2단계(뜨거움): 절전 모드와 같은 동작(단순한 유리, 최고 주사율 요청 해제, 백그라운드 작업 축소)
- 식은 뒤 30초가 지나야 되돌립니다. 경계에서 켜졌다 꺼졌다 하지 않게 하기 위함입니다.
- 손글씨 인식은 시스템 절전 모드에서도 미룹니다.
- 고른 설정은 바뀌지 않습니다. 모션 설정에 "지금은 그리지 않음"과 이유가 표시됩니다.

### 4. 모션 블러 기본값과 부분 선택 공개 (K06, K07)
- 부분별 켜기·끄기를 개발자 코드 없이 누구나 쓸 수 있게 했습니다.
- **노트 페이지 스크롤 블러는 기본 꺼짐**으로 바꿨습니다. 다섯 부분 중 가장 무겁고, 효과를 잰 적이 없기 때문입니다. 부분별 설정에서 켤 수 있습니다. 이미 직접 켜거나 끈 기기는 그 선택이 유지됩니다.

### 5. 사이드바가 움직이는 동안의 터치 (K16)
- 사이드바·페이지 패널·레이어 패널이 미끄러지는 동안에는 보이는 위치와 실제 터치 위치가 달랐습니다. 이제 멈출 때까지 터치를 받지 않아, 엉뚱한 버튼이 눌리지 않습니다.

### 6. 성능 기록 도구 (K24, K34)
- 설정 → 진단에 **성능 기록**을 넣었습니다(개발자 코드가 있는 기기). 시작한 뒤 평소처럼 쓰고 돌아와 멈추면, 프레임마다 걸린 시간이 하던 일별로 정리됩니다.
  - 구분: 필기 / 노트 페이지 이동 / 팝업·패널 이동 / 첫 화면 스크롤 / 그 밖의 터치 / 유휴
  - 항목: 프레임 수, 늦은 프레임 수, p50·p95·p99·최대, 늦은 프레임이 어디서 시간을 썼는지(UI 스레드, 그리기 명령, GPU)
  - 유휴 항목은 아무것도 안 만질 때 1초에 몇 프레임을 그렸는지 보여 줍니다. 가만히 있는데 숫자가 크면 그것이 발열 원인입니다.
- 결과는 복사하거나 공유할 수 있습니다. 노트 내용은 기록하지 않습니다.
- 앱 본 화면의 프레임만 셉니다. 팝업 창 자체의 프레임과, 화면에 실제로 빛이 나오기까지의 시간은 포함되지 않습니다.

### 7. 닫힌 메뉴는 조합하지 않음 (K37 일부)
- 메뉴는 처음 열 때까지 아무것도 만들지 않습니다. 첫 화면의 카드마다 붙은 ⋮ 메뉴가 카드가 나타날 때마다 상태와 코루틴을 만들던 것이 없어집니다.

### 8. 구버전 자동 시험 (K23 일부)
- Android 10·11·12 환경에서 주사율 읽기, 프레임 감시 시작·중지, 성능 기록, 펜 표시 방식 기본값, 블러 생성 여부를 확인하는 시험을 CI에 넣었습니다.

## 확인 방법

- 단위 테스트: 발열 단계와 30초 유지, 펜 표시 방식 선택표와 이전 설정 이어받기, 성능 기록의 분류·백분위·문구, 패널 이동 판정, 페이지 블러 기본값.
- Android 10·11·12 환경 시험(Robolectric).
- CI에서 릴리스 빌드와 전체 시험을 통과해야 게시됩니다.

## 하지 않은 것

**기기에서는 시험하지 않았습니다.** 아래는 이번에 만들지 않은 과제와 이유입니다.

- **측정이 먼저 필요한 것**: 유휴 주사율 낮추기(K18, 주사율이 바뀌는 순간 첫 획이 늦어지는지 재야 함), 저해상도 유리 배경(K35), 팝업 공용 호스트(K21), 확대 후 작업 분산(K13), 타일 첫 작업 제한(K12), 전역 메모리 예산(K09), 공통 작업 큐(K08), 썸네일 우선순위(K10). 이번에 넣은 성능 기록으로 실제 느린 곳을 확인한 뒤 진행합니다.
- **필기 경로 깊숙한 곳이라 기기 없이 바꾸면 위험한 것**: 획 표시→확정 전환 상태기계(K02), 손·펜·버튼 라우팅 정리(K04), 부분 지우개 예산(K14), 저장 스냅샷 분할(K20), 오래된 작업 취소(K19), 팝업 노트 비활성 창 정지(K15), 캐시 회수 후 복구(K31).
- **보류**: 홈 목록 읽기를 백그라운드로(K11, 이미 바뀐 노트만 다시 읽는 캐시가 있어 이득이 작고 삭제 직후 화면이 어긋날 위험이 있음), 웹 패널 추가 정지(K28), 연필 간소화(K25), 레이어 드래그 미리보기(K26), 시작 프로필(K30), 선택 이동 미리보기(K32), 필압 재작성(K42), 헤더 변형(K43), 성능 힌트 비교(K45), 언어 A/B(K33), 개발용 감시(K36), 오류 기록 파일(K38), 진단 UI 비용(K29).
- **해당 없음으로 확인**: 뷰포트 알림(K40)은 지금 받는 쪽이 없어 비용이 없습니다. 떠 있는 시계(K44)는 이미 글자가 바뀔 때만 다시 그립니다.

## 태블릿에서 해 볼 것

1. **Android 10 기기**: 앱이 열리는지, 설정 → 외관 → 모션이 열리는지 봅니다.
2. **펜이 안 써지던 기기**: 펜 설정에서 "지금 쓰는 방식"을 확인하고 100획쯤 씁니다. 그래도 안 보이면 방식을 바꿔 가며 어느 것이 되는지 알려 주세요.
3. **성능 기록**: 진단에서 기록을 시작하고 첫 화면 스크롤, 노트 열기, 확대, 팝업 열기, 필기, 30초 가만히 두기를 한 뒤 결과를 복사해 보내 주세요. 다음 작업 순서를 이 숫자로 정합니다.
4. 배터리 절약 모드를 켜고 모션 블러가 꺼지는지, 설정에 이유가 나오는지 봅니다.
5. 사이드바를 열자마자 버튼을 눌러 봅니다. 움직이는 동안에는 눌리지 않아야 합니다.
