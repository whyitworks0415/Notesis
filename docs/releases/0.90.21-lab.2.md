# Notesis Lab 0.90.21-lab.2 (213)

<!-- update: manual -->

> 수동 성능 실험판입니다. 기존 **Notesis Lab**의 업데이트이며 정식 Notesis와는 별도입니다. **About · Help → Check for updates** 또는 APK 링크로 설치할 수 있습니다.

## 부분 지우개와 편집 처리

- **긴 필기의 부분 지우개 구간 판정을 C++로 묶었습니다.** 점을 네이티브로 하나씩 전달하지 않고 직접 버퍼로 전달합니다. 작은 필기와 수치 경계에 가까운 판정은 기존 Kotlin 계산으로 돌아갑니다. 잘린 선의 끝점 보간도 기존 계산을 유지합니다.
- 지우개가 여러 선을 지울 때 좌표·결과 버퍼를 재사용합니다. 이전 선보다 짧은 선을 처리할 때도 실제 점 개수만 사용합니다.
- **선택한 필기의 확대·축소 시 최종 펜 굵기를 먼저 적용해 형상을 한 번만 생성**합니다. 기존에는 좌표 변환 후 굵기를 바꾸며 두 번 생성했습니다. 변화가 없는 변환도 생략합니다.
- **도형 인식의 반복 평활화**를 두 개의 좌표 버퍼로 처리합니다. 매 단계마다 작은 배열을 만들던 작업을 줄이며 끝점과 최종 좌표는 기존 계산과 동일하게 유지합니다.

## 필기 종료 처리

- 펜 종료 보정과 로딩 보정의 좌표·시간 배열을 작업 스레드별로 재사용합니다. 중첩 호출은 별도 배열을 쓰고, 큰 임시 입력은 공유 캐시에 남기지 않습니다.
- 입력 경로와 펜 종료 보정 기준 자체를 바꾸지 않았습니다. 노트 저장 형식·레이어·기존 필기는 유지합니다.

## 측정값 정정 및 분리

- **212의 front-buffer `first ink (submitted)` 값은 실제 제출 시간이 아니었습니다.** `startStroke`가 반환된 시점까지의 값이었으므로, 이전에 공유한 10.0ms/3.7ms는 화면에 잉크가 보인 시간으로 해석할 수 없습니다. 이번부터 이 측정을 `pen start handled`로 분리합니다.
- `first ink (render/post)`와 `wet ink (render/post)`는 Ink 렌더 완료 콜백 또는 호환 표면 제출에서만 기록합니다. 제공되지 않는 값은 `-`로 남기며 시작 처리 시간으로 대체하지 않습니다. 실제 픽셀이 빛나는 시점은 측정하지 않습니다.
- 기존 `pen-up finalize`는 유지하고 **`pen-up callback wait`와 `pen-up commit work (batch)`**를 추가했습니다. Ink 콜백을 기다리는 시간과 앱이 필기를 반영하는 작업을 구분할 수 있습니다.
- 측정 경계가 달라진 첫 잉크 항목은 이전 버전과 직접 비교하면 안 됩니다. 이전 front-buffer 첫 잉크 값은 새 `pen start handled`와 비교해야 합니다. 숫자 변경 자체는 성능 향상을 뜻하지 않습니다.

## 검증

- 로컬 전체 Debug 테스트 **660개**가 실패·오류·건너뜀 없이 통과했습니다.
- C++ 메모리·정의되지 않은 동작 검사에 새 지우개 커널을 포함했습니다. 기존 공간 검색의 4,540개 조회 검사와 지우개 700개 무작위 입력·잘못된 용량 검사를 통과했습니다.
- 실제 호스트 JNI를 통한 1,000개 무작위 지우개 동작을 기존 Kotlin 결과와 대조했습니다. 경계 근처는 기준 계산으로 돌아가며 잘못된 버퍼는 거부합니다.
- 도형 보정 결과의 좌표·끝점 일치, 재사용 배열의 남은 데이터, 중첩 보정, 초기화되지 않은 렌더 시각 처리도 검사했습니다.
- 릴리스 APK, 전체 release 단위 테스트, UI/JNI 검사, 기존 키 서명 검증을 통과한 뒤 사전 릴리스로 게시합니다.

실기기의 새 버전 필기 지연·프레임·배터리·발열 개선량은 아직 측정하지 않았습니다. 212 로그만으로 지연의 원인을 확정하지 않았으며 이번 변경으로 첫 잉크 문제가 해결됐다고 단정하지 않습니다.

같은 노트·확대율·밝기·유리 설정으로 부분 지우개, 선택 확대·회전·되돌리기, 긴 곡선의 도형 변환을 비교해 주세요. 새 로그에서는 시작 처리, 실제 렌더, 펜 종료 대기·작업 항목을 함께 확인해 주세요.
