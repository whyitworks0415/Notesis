# Notesis 0.99.6 (247)

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

> ⚠️ 0.91.0부터 앱은 **Material 화면만** 씁니다. Liquid glass·Glassmorphism을 계속 쓰려면 0.90.28에 머무르세요.

필기가 많은 페이지가 화면에 **나타나는 순간** 3~5fps로 떨어지던 문제를 렌더링 구조부터 바꿔서 손봤습니다.

## 원인
- 필기는 512px 타일 단위의 GPU 레이어로 그려집니다. 새 타일이 화면에 처음 나올 때는 그 안의 획 수천 개(메시)를 **RenderThread가 같은 프레임 안에서** 레이어에 칠해야 했습니다.
- 지금까지 프레임 예산은 UI 스레드가 "그릴 목록을 만드는 시간"만 쟀습니다. 목록 만들기는 빠르지만 실제로 칠하는 비용은 예산 밖이었습니다. 그래서 필기 많은 타일 몇 장이 한 프레임에 들어오면 그 프레임이 수백 ms가 됐습니다.
- 한 번 칠한 레이어는 캐시되기 때문에, 획이 다 나타난 뒤에는 덜 끊겼습니다.

## 바뀐 점
- **타일을 백그라운드에서 그림으로 칠합니다.** 새로 나타나는 타일, 확대·축소 뒤의 새 해상도 타일, 레이어 순서가 바뀐 페이지는 작업 스레드(코어의 1/3, 최대 3개)에서 비트맵으로 칠합니다.
  - 칠한 그림은 같은 스레드에서 그래픽 메모리로 옮긴 뒤 화면에 넘깁니다. RenderThread는 **완성된 그림만 그리면** 됩니다.
  - 타일이 준비되는 동안에는 저장된 페이지 그림이나 이전 해상도의 타일이 그 자리를 채우고, 준비된 타일부터 차례로 바뀝니다.
- **그동안 쓴 획은 바로 보입니다.** 그림이 칠해지는 중에 그 타일에 새로 쓴 획은 그림 위에 따로 그립니다. 그림이 완성되면 그 안에 들어간 획만 빼서 두 번 그려지지 않게 합니다. 필기 지연은 이 작업과 상관없습니다.
- 펜으로 쓰는 동안에는 백그라운드 칠하기를 **한 번에 한 타일만** 하게 해서 코어를 펜에 양보합니다.
- 쓴 획을 타일 그림에 합치는 정리 작업도 백그라운드로 옮겼습니다. 지금까지는 펜을 멈춘 뒤 타일 전체를 GPU로 다시 칠했습니다.
- **GPU로 칠해야 하는 타일에는 "프레임당 획 수" 상한을 뒀습니다.** 연필, 점선·입자 브러시 같은 획은 비트맵에 칠할 수 없어 여전히 GPU로 칠합니다. 이런 타일은 한 프레임에 칠하는 획 수를 쓰는 중 300, 움직이는 중 600, 멈춰 있을 때 1500개로 제한합니다. 단, 한 타일은 항상 먼저 칠합니다.
- 지우개·올가미 이동 같은 **편집**은 바로 보여야 하므로 지금처럼 GPU로 즉시 다시 칠합니다.
- 진단 정보에 "백그라운드에서 칠한 타일 수와 걸린 시간"을 추가했습니다.

## 어떻게 확인했나
- 빌드, 네이티브 커널 점검, 전체 단위 테스트(141개 클래스)를 통과했습니다. 프레임당 획 상한 정책에 테스트를 추가했습니다.
- 백그라운드로 칠하는 방식은 이미 페이지 그림·캡처에 쓰던 것과 같은 그리기 경로를 씁니다.

## 하지 않은 것 / 확인하지 못한 것
- **태블릿에서 돌려 보지 않았습니다.** fps가 얼마나 오르는지 숫자로 말할 수 없습니다.
- 백그라운드로 칠한 타일과 GPU로 칠한 타일은 획 가장자리의 부드럽게 처리(안티에일리어싱) 방식이 조금 다릅니다. 지우개로 편집한 타일이 GPU 방식으로 바뀔 때 획 굵기가 아주 미세하게 달라 보일 수 있습니다. 눈에 띄면 알려 주세요.
- **연필 필기가 많은 페이지는 이번 변경의 효과가 작습니다.** 이런 페이지는 GPU 방식과 프레임당 상한에만 기대므로, 덜 끊기는 대신 나타나는 데 조금 더 걸릴 수 있습니다.
- 플랜에 있던 "축소했을 때 획 정밀도 낮추기·페이지 한 장 그림"은 다음 버전에서 합니다.

## 태블릿에서 해 볼 것
1. 필기가 아주 많은 노트를 열고 빠르게 여러 페이지 넘기기 → 나타나는 동안 화면이 3~5fps로 떨어지던 것이 나아졌는지.
2. 확대·축소한 뒤 손을 떼기 → 새 해상도로 바뀌는 동안 끊기지 않는지.
3. 페이지가 막 나타나는 중에 바로 필기 → 쓴 획이 사라지지 않는지.
4. 지우개·올가미로 편집한 부분이 다른 부분과 다르게 보이지 않는지.
5. 진단 → 내보내기에 "tiles painted off the render thread" 줄이 늘어나는지(백그라운드 칠하기가 실제로 쓰이는지 확인용).
