## iOS 유리를 절반 해상도로 계산합니다
- 지금까지 유리는 화면 해상도 그대로, 유리 면의 모든 픽셀마다 블러와 렌즈를 계산했습니다. 툴바, 버튼, 팝업이 크고 많을수록 GPU 일이 늘어나는 구조였습니다.
- 이제 iOS 유리는 뒤 페이지를 **작은 층**에 그리고, 거기서 블러와 렌즈를 계산한 뒤 유리 면 크기로 늘려 그립니다. 앱이 직접 만든 그리기 노드(`LowResGlass`)입니다.
  - 절반 해상도면 면마다 GPU 일이 약 4분의 1이 됩니다.
  - 4분의 1 해상도면 약 16분의 1이 됩니다.
- 서리는 원래 흐린 것이라 거의 같아 보입니다. 맑은 층 아래로 비치는 페이지와 테두리의 가는 빛은 조금 부드러워집니다.
- **설정 → 모양 → Glass(iOS) → 유리 해상도:** 전체 / 절반(기본) / 4분의 1. "전체"는 지금까지의 유리입니다.
- Efficient glass가 켜져 있거나, 사이드 패널처럼 위에 다른 유리가 얹히는 면은 지금처럼 전체 해상도로 그립니다.

## 페이지 밖 필기가 많을 때 스크롤·확대·축소가 느리던 것
- **원인:** 페이지 밖(화이트보드) 필기는 512 단위 칸마다 기록해 두지만, 그 기록이 획의 도형(메시)이었습니다. 그래서 스크롤과 확대·축소의 매 프레임마다 GPU가 모든 획을 다시 그렸습니다. 페이지 안 필기는 그림으로 저장되어 있어서 이 비용이 없습니다.
- **수정:** 각 칸을 GPU 텍스처로 한 번 그려 두고, 바뀌지 않는 동안은 놓기만 합니다. 한 칸이 너무 크면(2048×2048 픽셀, 16MB 초과) 메모리를 아끼려고 예전처럼 그립니다.
- 매 프레임 칸마다 획을 하나씩 비교하던 확인도, 화이트보드가 바뀐 뒤에만 하도록 했습니다. 필기가 많을수록 CPU 일이 줄어듭니다.
- 확대·축소하는 동안에는 칸 그림이 늘어나 보여서 잠깐 흐릴 수 있습니다. 손을 떼면 그 배율로 다시 그립니다. 페이지가 확대·축소될 때와 같습니다.

## Ask agent: 키보드의 줄바꿈 키
- 태블릿 키보드의 줄바꿈 키(↵)가 메시지를 보내던 것을 **줄바꿈**으로 바꿨습니다.
- 보내기는 **Send** 버튼으로 합니다. 하드웨어 키보드에서는 **Ctrl+Enter**로도 보낼 수 있습니다.

## C++/Rust에 대하여
- 이번에도 느린 원인은 계산 코드가 아니라 GPU가 너무 많은 픽셀을 그리는 것이었습니다. 그래서 언어를 바꾸지 않고 그리는 양 자체를 줄였습니다. 셰이더는 원래 GPU에서 돕니다.

## 어떻게 확인했나
- CI의 릴리스 빌드, Lint, 단위 테스트, 스크린샷 테스트로 확인합니다. 새 테스트는 유리 해상도 설정의 저장·복원과 기본값입니다.
- **태블릿에서 확인하지 못했습니다. 얼마나 빨라졌는지 측정하지 않았습니다.** 절반 해상도의 모양은 기기에서 봐야 합니다.
- 화이트보드 칸 텍스처와 해상도를 줄인 유리는 스크린샷 테스트 환경(GPU 없음)에서 실제로 그려지지 않습니다.

## 태블릿에서 해 볼 것
1. iOS에서 팝업, 메뉴, 스크롤 → 전보다 덜 버벅이는지.
2. 유리 해상도를 전체 / 절반 / 4분의 1로 바꿔 가며 → 모양과 속도 차이.
3. 페이지 밖에 필기가 많은 노트에서 스크롤, 확대, 축소 → 덜 끊기는지. 확대 뒤 손을 떼면 다시 선명해지는지.
4. Ask agent에서 줄바꿈 키 → 줄이 바뀌고 보내지지 않는지. Send 버튼으로 보내지는지.
