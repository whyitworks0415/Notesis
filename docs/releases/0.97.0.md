# Notesis 0.97.0 (238)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

> ⚠️ 0.91.0부터 앱은 **Material 화면만** 씁니다. Liquid glass·Glassmorphism을 계속 쓰려면 0.90.28에 머무르세요.

Termux 설정 스크립트에서 **Gemini CLI**도 고를 수 있게 했습니다.

## 바뀐 점
- 에이전트 패널 → **이 태블릿에서**의 선택지에 Gemini CLI가 Claude Code, Codex, OpenCode와 나란히 나옵니다. 체크하고 설정 스크립트를 실행하면 설치, Notesis 연결(`~/.gemini/settings.json`), 안내 넣기(`~/.gemini/GEMINI.md`의 `<!-- notesis:start -->`~`<!-- notesis:end -->` 사이만, 직접 쓴 줄은 그대로)까지 합니다.
- Gemini CLI는 Node 20 이상이 필요하고 Debian 기본 Node는 그보다 낮아서, Gemini를 고른 경우에만 스크립트가 `n`으로 Node 20을 먼저 받습니다. 이 단계가 실패하면 Gemini만 "not set up"으로 표시되고 나머지 에이전트는 그대로 설정됩니다.
- 릴리스 규칙이 바뀌었습니다: 앞으로는 새 기능도 통과하면 바로 릴리스하고, 하지 말라고 하실 때만 보류합니다(AGENTS.md).

## 어떻게 확인했나
- 가짜 명령으로 설정 스크립트를 두 번 실행해 Gemini 설정 파일이 만들어지고 한 번만 들어가는지 확인했습니다. 단위 테스트(AgentSetupTest, AgentUiTest) 통과.

## 하지 않은 것
- **태블릿에서 실제로 설치해 보지 않았습니다.** 특히 `n`으로 Node를 바꾸는 단계가 Termux의 proot Debian에서 되는지, Gemini CLI의 MCP 설정 형식이 현재 버전과 맞는지는 기기에서만 알 수 있습니다.

## 태블릿에서 해 볼 것
1. 에이전트 패널에서 Gemini CLI만 체크하고 설정 스크립트를 복사해 Termux에서 실행.
2. 끝나면 새 Termux 세션 → `notesis-agents` → `node -v`(20 이상) → `gemini`. 처음에는 Google 로그인.
3. `gemini` 안에서 `/mcp`로 `notesis`가 보이는지 확인.
