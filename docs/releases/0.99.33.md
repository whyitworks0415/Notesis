## 쓴 뒤에 필기가 살짝 바뀌던 문제
### 원인으로 본 것
- 새로 쓴 획은 처음에 GPU가 바로 그립니다.
- 잠시 뒤 손이 쉬면, 그 획이 들어 있는 타일 전체를 **CPU로 다시 칠해서** 바꿔 끼웠습니다. 0.99.6부터 넣은 성능 최적화입니다.
- CPU로 칠한 그림은 가장자리 처리(안티에일리어싱)가 GPU와 조금 달라서, 쓴 지 잠깐 뒤 필기가 부드럽게 바뀌는 것처럼 보였습니다.

### 바뀐 점
- 새로 쓴 획을 타일에 합칠 때 **GPU로, 처음 그린 방식 그대로** 합칩니다. 쓴 획은 더 이상 나중에 바뀌지 않습니다.
- 페이지를 처음 열 때나 배율을 바꿀 때 배경에서 칠하는 최적화는 그대로입니다.
- 펜을 뗀 순간 시작·끝의 작은 갈고리를 정리하는 동작은 그대로 둡니다. 이것도 바로 바뀌는 게 싫으면 아래 개발자 모드에서 끌 수 있습니다.

## 개발자 모드: 필기 파라미터
설정 → **진단** 맨 위의 **개발자 모드**를 켜면 "필기 파라미터"가 나타납니다. 값은 다음 획부터 적용되고, **기본값으로 되돌리기**를 누르면 모두 원래대로 돌아갑니다.

**지금 쓰는 펜** (펜 설정과 같은 값을 여기서도 바꿉니다)
- 예측: 끔 / 자동 / 4·8·12ms
- 손떨림 보정 세기(0–100), 구간 평균 방식
- 필압 반응(0–40, 10이 펜 그대로)

**펜을 뗀 뒤**
- 새 필기를 배경에서 합치기 (기본 꺼짐: 이번 수정)
- 펜을 뗄 때 끝 정리 (기본 켜짐)

**쓰는 동안**
- 화면 주사율 유지 (0.99.28의 1픽셀, 기본 켜짐)
- 모든 주사율에서 필기 잔상 (기본 꺼짐)
- 쓰는 동안 CPU 빠르게 (기본 켜짐)

**페이지의 필기**
- 메시 정밀도 (0.25–4배, 1이 기본): 낮추면 곡선이 더 매끄럽고 작업이 늘어납니다.
- 프레임당 타일 예산 (0.25–4배)
- 타일을 배경에서 칠하기 (기본 켜짐)
- 프레임이 밀리면 필기 작업 줄이기 (기본 켜짐)

## 필기감
- 이번 버전에서 필기감에 바로 영향을 주는 변경은 "쓴 뒤 바뀌지 않게"입니다.
- 나머지는 태블릿에서 직접 느껴 봐야 해서 개발자 모드로 조절할 수 있게 했습니다. 예측, 손떨림 보정, 필압, 끝 정리, 메시 정밀도를 바꿔 보시고 좋았던 조합을 알려 주시면 기본값으로 반영하겠습니다.

## 어떻게 확인했나
- 빌드, 축소(R8) 릴리스 빌드, Android 버전 검사(Lint), 네이티브 커널 점검, 전체 단위 테스트(157개 클래스)를 통과했습니다.
- 메시 정밀도 계산과 기본값에 테스트를 추가했습니다.

## 하지 않은 것 / 확인하지 못한 것
- **태블릿에서 직접 써 보지 않았습니다.** 쓴 뒤 바뀌는 원인은 코드에서 찾은 것이며, 측정으로 확인하지는 않았습니다.
- 새 획을 GPU로 합치면, 손이 쉴 때 UI 스레드가 타일을 다시 기록하는 일을 맡습니다. 필기가 아주 많은 페이지에서 펜을 뗀 직후 버벅이면 알려 주세요. 개발자 모드에서 "새 필기를 배경에서 합치기"를 켜면 예전 방식으로 돌아갑니다.

## 태블릿에서 해 볼 것
1. 글씨를 쓰고 1–2초 지켜보기: 펜을 뗀 뒤 필기가 더 이상 바뀌지 않는지.
2. 진단 → 개발자 모드 켜기 → 예측·보정·필압·끝 정리를 바꿔 가며 필기감 비교하기.
3. 필기 많은 페이지에서 계속 쓸 때 버벅임이 없는지.
