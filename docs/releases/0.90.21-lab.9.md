# Notesis Lab 0.90.21-lab.9 (220)

<!-- update: manual -->

> 수동 Lab 업데이트입니다. 기존 Notesis Lab 위에 설치합니다. 일반 Notesis와 패키지·데이터·업데이트 경로가 분리됩니다.

## 첫 화면 iOS 스크롤

- iOS 등 굴절 유리 외관의 노트·폴더 카드를 화면에 있는 동안 그래픽 레이어로 합성합니다. 목록 이동 시 테두리·그라데이션·미리보기를 매 프레임 다시 칠하는 비용을 줄이기 위한 변경입니다. 카드가 사라지면 Lazy 목록의 수명에 따라 해제되며, 전체 노트 수만큼 이미지 캐시를 추가하지 않습니다.
- 스크롤 중에는 상단 유리 헤더도 레이어로 합성합니다. 기존 배경 촬영 일시 정지와 함께 사용하며, 스크롤 종료 후 최신 배경을 다시 반영합니다. 헤더 접힘·선택·버튼 애니메이션은 계속 갱신됩니다.
- Lazy 목록이 폴더·필기 노트·Markdown 노트를 종류별로 재사용하도록 구분했습니다.
- 셀 재사용 또는 같은 경로의 썸네일 교체 후 이전 그림이 남을 수 있던 상태 보관 문제를 수정했습니다. 파일 디코딩은 계속 작업 스레드에서 실행합니다.
- 원래 유리의 굴절·색·테두리와 팝업 모션은 유지합니다. 효율 유리 설정을 강제로 켜지 않습니다. Material에는 카드 합성 레이어를 추가하지 않습니다.

## 검증과 한계

- Kotlin/Compose 회귀 테스트: 긴 혼합 목록 왕복 이동 후 노트·폴더 터치, 다크 테마 전환, 썸네일 파일 변경·같은 경로 덮어쓰기·제거·캐시 복귀.
- 로컬 전체 회귀 테스트 717개 통과(실패·오류·건너뜀 0), C++ 주소/정의되지 않은 동작 sanitizer 및 정확성 검사 통과.
- 배포 전 CI APK 빌드와 서명을 별도로 검증합니다.
- 그래픽 레이어는 화면에 보이는 카드 등의 GPU 메모리를 더 사용하는 대신 반복 렌더링을 줄이는 절충입니다. 실제 GPU 캐시 유지와 개선 폭은 기기·드라이버에 따라 다릅니다.
- 실제 Android 태블릿에서 실행하거나 홈 스크롤 프레임·전력·발열을 측정하지 않았습니다. Robolectric 테스트는 기기 GPU 성능을 검증하지 않습니다.

## 태블릿에서 확인

1. 노트가 많은 첫 화면에서 iOS 외관으로 빠르게 아래·위로 반복 이동합니다. 120Hz와 60Hz에서 Lab.8과 같은 목록으로 비교합니다.
2. 스크롤 후 헤더의 배경이 갱신되는지, 검색·폴더·다중 선택·카드 메뉴가 정상인지 확인합니다.
3. 썸네일 변경 후 다른 카드 그림이 남지 않는지, 다크 모드 전환 후 카드가 정상적으로 갱신되는지 확인합니다.
4. 목록을 오래 왕복한 후 메모리 사용과 홈 복귀 동작을 확인합니다.
