## S6 Lite: 필기 중 화면 버퍼를 기다리는 일을 메인 스레드에서 뺌
S6 Lite에서 보내 주신 측정값에서 원인이 보였습니다.

- **compat surface lock p50 11.6ms, p95 29.7ms**: 한 프레임은 16.7ms입니다. 필기하는 동안 메인(UI) 스레드가 매 프레임 그중 약 12ms를, 화면이 그릴 버퍼를 돌려주기를 기다리며 멈춰 있었습니다.
- 그동안 다음 펜 입력 처리도 밀렸습니다(**input handled p50 14.1ms**). 툴바·페이지 같은 다른 화면 일도 남은 4~5ms 안에 해야 했습니다.

이번 버전부터 이렇게 바뀝니다.
- 메인 스레드는 잉크를 화면 크기의 비트맵에 그리기만 하고(p50 약 3ms) 바로 다음 일로 넘어갑니다.
- 버퍼를 기다리고 화면에 올리는 일은 **별도 스레드**가 합니다.
- 그 스레드는 버퍼를 받은 **뒤에** 비트맵을 복사합니다. 그래서 기다리는 동안 들어온 펜 입력도 같은 프레임에 나갈 수 있습니다(바뀐 곳 주변 48px까지).
- 펜을 뗀 뒤 남은 잉크를 지울 때도 화면 전체를 다시 그리지 않고 그렸던 곳만 지웁니다.

비트맵 하나(S6 Lite 화면 기준 약 9.6MB)를 더 씁니다. 메모리가 부족해 비트맵을 만들지 못하면 예전처럼 창 안에 그리는 방식으로 돌아갑니다.

## 측정값의 다른 부분
- **pen-up finalize p95 544ms**: Ink 라이브러리가 끝난 획을 다음 획이 끝날 때 함께 돌려주는 시간입니다. 빠르게 이어 쓸 때 길어집니다. 그동안 획은 화면에 계속 보이므로 눈에 보이는 지연은 아닙니다.
- **battery saver on**: 절전 모드에서는 CPU가 느려지고, 앱도 펜 끝 앞의 예측 선을 끕니다. 둘 다 "느리다"는 느낌을 키웁니다.
- **GC +768**(약 13분 동안): 할당량(0.3MB/s)에 비해 많습니다. 원인은 아직 찾지 못했습니다. 대부분 백그라운드에서 도는 수집이라 이번에는 바꾸지 않았습니다.

## 확인 방법
- 코드와 빌드로 확인했습니다. **기기에서 얼마나 나아졌는지는 재지 않았습니다.**
- 기대하는 변화: input handled가 크게 줄고(p50 14ms → 몇 ms), wet ink의 p95(46.9ms)가 줄어드는 것. compat surface lock 값 자체는 이제 별도 스레드의 대기 시간이라 비슷하게 나올 수 있습니다.

## 기기에서 확인할 것
- **절전 모드를 끄고** 진단에서 Reset counters → 1~2분 필기 → Copy measurements를 다시 보내 주세요(0.85.2와 비교)
- 빠르게 쓸 때 선이 덜 끊기고 덜 늦는지
- 획을 다 쓰고 펜을 뗐을 때 획이 깜빡이거나 잠깐 사라지지 않는지
- 지우개 커서(원)가 잘 따라오고 흔적이 남지 않는지
- 화면 회전, 분할 화면, 앱 전환 후 돌아왔을 때 잉크가 제대로 나오는지(이전 획의 잔상이 남지 않는지)
