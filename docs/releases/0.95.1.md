# Notesis 0.95.1 (236)

<!-- update: manual -->

> 수동 업데이트입니다. 앱이 먼저 알리지 않으며, **About · Help → Check for updates**에서 설치할 수 있습니다.

> ⚠️ 0.91.0부터 앱은 **Material 화면만** 씁니다. Liquid glass·Glassmorphism을 계속 쓰려면 0.90.28에 머무르세요.

0.95.0의 **Termux 설정 스크립트**(에이전트 패널 → 이 태블릿에서)에서 에이전트 하나가 설치되지 않으면 전체가 멈추던 결함을 고친 수정판입니다.

## 바뀐 점

### 설정 스크립트: 하나가 실패해도 나머지는 계속
- **문제**: 0.95.0의 스크립트는 고른 에이전트를 `npm install -g` 한 번에 설치하고, 중간에 하나라도 실패하면 스크립트 전체를 멈췄습니다. 실제로 OpenCode의 설치 단계(`opencode-ai`의 postinstall)가 "Binary not found"로 실패하자, 함께 고른 Claude Code와 Codex도 설치·연결되지 않았습니다.
- **고침**:
  - 에이전트를 하나씩 설치합니다. 설치가 끝나고 실행 파일이 실제로 생겼을 때만 그 에이전트를 Notesis에 연결합니다.
  - 하나가 실패해도 나머지는 계속하고, 끝에 **무엇이 설정되지 않았는지**("not set up: OpenCode")를 알려 줍니다. 모두 됐을 때만 `done`이라고 합니다.
  - 설치 중 임시 파일을 `/tmp`가 아니라 홈 폴더(`~/.notesis/tmp`)에 만들고, 끝나면 지웁니다. OpenCode는 약 211MB짜리 프로그램을 임시 폴더에 푼 뒤 복사하기 때문입니다.
  - 홈 폴더의 남은 공간이 1GB 미만이면 시작할 때 알려 줍니다.
- 다시 실행해도 설정이 겹치지 않는 것은 그대로입니다.

## 확인 방법
- 이 컨테이너에서 앱과 시험을 빌드했고, 설정 스크립트 시험을 늘렸습니다: Termux와 Debian의 도구 대신 흉내 내는 대체 프로그램으로 스크립트를 실제로 두 번 실행해 결과를 확인했고, **OpenCode 설치만 실패하게 한 경우**도 시험했습니다(Claude Code와 Codex는 설정되고, OpenCode는 설정 파일을 쓰지 않으며, 끝에 안내가 나옴).
- OpenCode 패키지를 읽어 보니 `opencode-linux-arm64` 패키지 안에는 `bin/opencode`(211MB)가 정상으로 들어 있었습니다.

## 하지 않은 것
- **OpenCode가 왜 풀린 뒤 파일이 없다고 나왔는지는 확인하지 못했습니다.** 패키지는 정상이라 태블릿의 Debian 쪽(임시 폴더의 공간이나 압축 풀기)이 유력하지만 추정입니다. 이번 수정은 임시 폴더를 홈 폴더로 옮겨서 그 경우를 피하려는 것이고, 실제로 고쳐지는지는 기기에서만 알 수 있습니다.
- 실제 Termux와 태블릿에서는 돌려 보지 못했습니다.

## 태블릿에서 해 볼 것
1. 이 버전으로 업데이트한 뒤 에이전트 패널에서 **설정 스크립트를 다시 복사**해 Termux에 붙여 넣으세요(앞서 실행한 것이 있어도 다시 해도 됩니다).
2. 끝에 `done`이 나오는지, 아니면 `not set up: …`이 나오는지 알려 주세요. OpenCode가 또 실패하면 `df -h`의 결과와 오류 화면을 보내 주세요.
3. `notesis-agents` → `claude`로 들어가 "노트 목록 보여 줘"라고 해 보세요.
