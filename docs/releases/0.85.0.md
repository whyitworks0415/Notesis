## 펜 버튼 레이저 포인터 (U01)
- **Settings › Touch & gestures › Pen and page**의 "Writing with the pen button held"에 **Points (laser)**가 생겼습니다.
- 펜 버튼을 누른 채 쓰면, 쓰지 않고 화면 위를 빨갛게 가리킵니다. 펜 뒤로 0.65초 동안 사라집니다.
- **Laser pointer leaves a trail**을 끄면 자국 없이 펜 끝에 점만 보입니다.
- 노트에는 아무것도 남지 않습니다. 획, 되돌리기, 손글씨 색인, PDF 내보내기 어디에도 들어가지 않습니다. 펜을 떼면 쓰던 도구 그대로입니다.
- 툴바의 레이저 도구는 예전에 빼신 대로 다시 넣지 않았습니다. 예전에 저장된 레이저 설정은 계속 지우개로 동작합니다.
- 펜을 떼었다 다시 대면 앞 자국과 이어지지 않습니다(읽기 모드의 자국도 같습니다).

## 캡처 링크를 양쪽으로 (같은 노트 안)
- 노트의 한 부분을 캡처해 **같은 노트**의 다른 페이지에 붙이면, 원래 페이지 가장자리에 "{N}쪽에 복사함" 탭이 생깁니다. 누르면 붙인 페이지가 열립니다. 붙인 그림은 전처럼 원래 페이지로 이어집니다.
- 다른 노트에 붙인 경우는 지금처럼 한쪽 링크입니다. 그 노트가 열려 있지 않아 고칠 수 없기 때문입니다.

## Markdown 읽기 모드의 callout
- 읽기 모드에서 `> [!note] 제목` 같은 callout이 종류별 색, 제목, 테두리로 보입니다. 지금까지는 기울어진 인용문으로만 보였습니다.
- `[!note]+`(펼쳐짐)와 `[!note]-`(접힘)는 제목을 눌러 접고 펼칠 수 있습니다.
- 종류: note·info(파랑), tip·success(초록), question(노랑), warning(주황), danger·error·bug(빨강), example(보라), quote(회색). 모르는 종류는 note처럼 보입니다.
- PDF로 만들 때의 callout과 같은 표시를 씁니다.

## Markdown 정리 (M01, M03)
- 저장소의 `docs/markdown-render-paths.md`에 편집·읽기·PDF 각각에서 무엇이 보이는지 표로 정리했습니다(수식, 코드 색, 포함, 표 등).
- PDF 경로의 HTML 안전성을 확인했습니다. Markdown 안의 스크립트는 실행되지 않습니다(JavaScript 다리 없음, 파일 접근 꺼짐, 앱 스크립트만 허용, 네트워크·이동 차단). 고칠 것은 없었습니다.

## 하지 않은 것과 이유
- **필압을 가볍게 0.5초 유지하면 임시 지우개(Notein)**: 쓰던 획을 지우개로 바꾸는 핵심 필기 경로를 고쳐야 하고, 이미 있는 "길게 눌러 도형"과 겹칩니다. 문서도 기기에서 값(압력·시간)을 맞춰 봐야 한다고 해서 넣지 않았습니다.
- **툴바 도킹 상태 정리(U02), 모든 메뉴 정리(U06), 창마다 다른 레이어 보이기**: 화면 구성 전체를 바꾸는 일이라 기기에서 비교한 뒤 따로 하겠습니다.
- **`![[노트]]` 실제 포함, backlinks 색인, 편집기 증분 분석(M02)**: 큰 보관함과 긴 문서에서 먼저 재 보라는 권고라 이번에는 표만 만들었습니다.
- **실기기 측정(N02), 다른 앱 엔진 추적(O01), Noteshelf 곡선 실험(E02)**: 0.84.0에서 설명한 대로입니다.

## 기기에서 확인할 것
- 펜 버튼을 "Points (laser)"로 두고 누른 채 쓰면 빨간 자국이 사라지는지, 노트에 아무것도 남지 않는지, 떼면 원래 펜으로 쓰이는지
- 같은 노트 안에서 캡처를 붙인 뒤 원래 페이지에 탭이 생기고, 누르면 붙인 페이지가 열리는지
- Markdown 읽기 모드에서 callout이 색과 제목으로 보이고 +/-가 접히는지
