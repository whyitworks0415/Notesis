# Notesis 0.34.4 (91)

메시 렌더링을 켠 상태에서 필기가 많은 페이지를 이동하거나 편집할 때 발생하는 지연을 줄였습니다.

## 변경 사항

- 페이지 전체의 메시 명령을 매 프레임 실행하던 방식에서 화면에 보이는 512px 타일의 GPU 결과를 재사용하는 방식으로 바꿨습니다. 확대가 멈추면 현재 배율로 다시 만들며 저장된 획과 브러시 정밀도는 유지합니다.
- 새 필기는 기존 캐시 위에 별도로 그립니다. 필기가 잠시 멈추거나 한 타일에 새 획이 32개 쌓이면 해당 타일만 갱신합니다.
- 지우개·실행 취소·색 변경은 변경된 획이 걸친 영역만 갱신합니다. 화면 밖에 추가된 획은 화면 안의 캐시를 다시 만들지 않습니다.
- 올가미 이동 중에는 선택된 획만 다시 그리고 나머지 필기는 캐시를 재사용합니다. 올가미 선택도 공간 인덱스로 후보를 좁힙니다.
- 형광펜의 위/아래 순서와 Multiply 합성을 보존했습니다. 타일 경계의 중복 합성을 막고 2px 여유 영역으로 가장자리 처리를 유지합니다.
- 타일의 GPU 픽셀 캐시를 일반 기기 48MiB, 저메모리 기기 24MiB로 제한합니다. 메모리 수치는 픽셀 버퍼 기준이며 획 데이터와 드라이버 자원은 별도입니다.
- Android가 화면 밖의 그리기 명령을 해제한 뒤 돌아오는 경우 원본 획으로 복구합니다. 기존 일반 렌더링에도 같은 복구 검사를 적용했습니다.
- 메시를 재생성한 뒤 공간 인덱스가 오래된 획을 계속 참조할 수 있던 문제를 고쳤습니다.
- 디버깅 창에 메시 캐시 타일 수, 용량, 해당 화면에서 재기록한 획 수를 추가했습니다.

## 검증

- JVM 단위 테스트 142개와 전체 Android 회귀 검사 통과.
- 3,000획이 있는 실제 View에 24획을 연속 입력해 기존 필기와 새 필기 총 3,024획 보존 확인. 유리 배경 중복 그리기 중단, 설정 슬라이더·팔레트·지우개, 아이콘, PDF, 저장 및 클라우드 통합 기능 검사도 통과했습니다.
- GPU 원본/캐시 비교: 새 획, 빈 타일에 추가한 획, 화면 밖 이동 후 복귀, 지우기, 올가미, 메시 교체, 형광펜 순서, 8배 확대 검사 통과. 주요 정수 좌표 장면은 픽셀이 일치하며 소수점 이동에서는 캐시 픽셀 재샘플링으로 가장자리 차이가 생길 수 있습니다.
- 별도 GPU 표면을 사용한 동일 3,000획 장면의 마지막 독립 측정: 프레임 처리 p50 **20.3 → 6.2ms**, p95 **22.7 → 7.1ms**. 5프레임 준비 후 36프레임을 측정했으며 GPU 표시 완료를 포함합니다. Android 36.1 x86_64 / SwiftShader / 1024×768 결과입니다.
- arm64 release 빌드와 APK v2 서명 검증 통과.
- 에뮬레이터의 제스처 내비게이션/작업 썸네일 오류를 피하도록 테스트 환경과 테스트 창만 조정했습니다. 제품 창에는 적용하지 않습니다.

실제 태블릿의 S Pen 지연과 장시간 발열은 별도 확인이 필요합니다. 위 수치는 에뮬레이터의 비교 장면 측정입니다.
