# Notesis Lab 0.90.21-lab.5 (216)

<!-- update: manual -->

> 수동 성능 실험판입니다. 기존 **Notesis Lab**의 업데이트이며 정식 Notesis와는 별도입니다. **About · Help → Check for updates** 또는 APK 링크로 설치할 수 있습니다.

## 이번 빌드의 목적

노트 열기를 체감상 빠르게 하는 변경 하나와, 일반 버전·Lab·스위치별 차이를 **태블릿에서 같은 조건으로 잴 수 있는 도구**를 넣었습니다. 이 빌드의 어떤 것도 기기에서 실행해 보지 못했습니다.

## 바뀐 점

### 1. 노트 열기: 페이지 그림 먼저 보여 주기
- 노트를 열 때 걸리는 시간의 대부분은 획 형상을 다시 만드는 일입니다(코드 주석 기준). 그동안 페이지는 빈 종이로 보였습니다.
- 이제 노트를 나갈 때 **보고 있던 페이지의 잉크를 그림으로 저장**하고, 다음에 열 때 실제 잉크가 준비될 때까지 그 그림을 보여 줍니다. 실제 잉크가 들어오면 0.25초 동안 그림을 밑에 깔아 두었다가 뺍니다.
- 그림은 캐시 폴더에 두며, 노트 파일 형식은 바꾸지 않았습니다.
- 그림을 쓰지 않는 경우:
  - 페이지 파일이 그림을 찍은 때와 달라진 경우(저장할 때마다 그림을 지웁니다)
  - 마스킹 테이프가 있는 페이지(그림에는 잉크만 있어서, 가려 둔 답이 잠깐 보일 수 있기 때문입니다)
  - 연필·입자 브러시가 있는 페이지(비트맵에 그려지지 않습니다)
  - 반투명 레이어가 있는 노트, 잠긴 노트, 획이 40개 미만인 페이지
- 형광펜은 그림에서 색이 조금 다르게 보일 수 있고, 실제 잉크가 들어오는 즉시 그림을 뺍니다.
- 실제 열기 시간이 줄어드는 것은 아닙니다. 빈 종이 대신 내용이 먼저 보이는 것입니다.

### 2. 노트 열기 계측
- 노트를 누른 때부터 **첫 프레임, 잉크가 보일 때, 실제 잉크가 다 만들어질 때**까지를 열 때마다 기록합니다.
- 설정 → Diagnostics → **Benchmark (Lab)** 카드의 Notes opened에 최근 5번이 나오고, 측정값 복사에도 들어갑니다.
- 그리기 호출 시점 기준이고, 화면에 빛이 나오는 시점은 아닙니다.

### 3. 벤치마크 실행기
- 같은 카드의 **Run benchmark**를 누르면 정해진 순서로 실행합니다.
  1. 보이는 페이지에 고리 모양 줄 30개를 펜 이벤트(목표 초당 250개)로 임시 표시한 뒤 지웁니다. 저장된 필기와 실행 취소·다시 실행 기록에는 넣지 않습니다.
  2. 페이지를 아래로 한 번, 위로 한 번 미끄러뜨립니다(손으로 튕길 때와 같은 코드).
  3. 쓰기 단계별 시간, 프레임 통계, 노트 열기 기록, 기기·빌드·스위치 상태를 보고서로 보여 주고 복사할 수 있습니다.
- 재생하는 동안에는 꾹 눌러 도형, 원 그려 선택, 낙서 지우기, 체크박스·첨부 탭 누르기가 동작하지 않게 해서 기존 필기를 건드리지 않게 했습니다.
- **중지·뒤로 가기·앱이 백그라운드로 이동할 때 임시 획과 예약된 입력을 정리**합니다. 취소 후 늦게 도착하는 완료 콜백도 실제 노트에 저장하지 않습니다. 벤치마크 중 실제 펜 입력은 측정용 획에 섞지 않으며, 도구가 바뀌면 쓰기 재생을 중단합니다.
- 종료·중지 후 원래 도구로 돌아갑니다. 필기 중이거나 아직 로딩 중인 페이지에서는 시작하지 않습니다.
- 한계: 펜 이벤트는 앱이 보낸 것이라 디지타이저에서 앱까지의 지연은 숫자에 없습니다. 프레임을 제출한 뒤 화면에 보일 때까지의 시간도 없습니다. **저장과 실행 취소 기록을 갱신하는 비용은 측정에서 제외**됩니다. 임시 획은 별도 표시로 직접 그리므로 일반 필기의 타일 캐시 갱신 경로와도 다릅니다. 같은 스크립트의 조건별 비교에 사용하고 일반 필기의 전체 종료 처리 시간과 같은 값으로 해석하면 안 됩니다.

### 4. 네이티브 충돌 보호
- 네이티브 코드의 오류는 앱을 바로 끝냅니다. 앱이 **두 번 연속 정상 종료되지 않으면** 다음 실행에서는 네이티브 코드(검색 트리, 지우개 계산, 자체 버퍼 표시)를 불러오지 않고 Kotlin 경로로 동작합니다.
- Diagnostics → **Native code (Lab)**에서 상태를 보고 다시 켤 수 있습니다.
- 네이티브가 아닌 원인의 비정상 종료도 같이 셉니다. 안전 모드이지 원인 판정이 아닙니다.
- 앱의 초기화 단계에서 충돌해도 횟수를 기록합니다. 다시 켜기를 눌러도 해당 실행 중에는 보호를 유지하고 다음 앱 실행부터 적용합니다.

## 하지 않은 것

- **필압 끈 펜의 이벤트 복사 제거**: 하지 않았습니다. lab.4에서 넣은 Pressure rewrite 숫자를 아직 받지 못해, 바꿀 만큼 큰지 모릅니다.
- **PDF 처리를 C++/Rust로 교체**: 하지 않았습니다. 외부 라이브러리를 새로 들여와야 하고 기기 없이 검증할 수 없는 크기입니다.
- **일반 버전에 같은 계측 넣기**: 이 브랜치는 Lab 전용이라 하지 않았습니다. 일반 버전과 비교하려면 일반 버전에도 벤치마크 실행기를 넣어야 합니다.
- 올가미 후보 찾기, 노트 검색, 백업 가져오기는 확인해 보니 이미 색인·기능이 있어 바꾸지 않았습니다.

## 확인한 것

- CI의 네이티브 검사, 단위 테스트, 릴리스 빌드(최종 Actions 실행에 기록).
- 새 테스트: 그림을 저장할 조건, 그림 크기 한도, 페이지 파일이 바뀌면 그림을 거부하는지, 충돌 횟수 계산, 벤치마크 획이 페이지 가운데 안에 있는지, 보고서와 열기 기록의 형식.
- 추가 검증: 임시 획의 실행별 분리와 취소 후 콜백 거부, 시작 중 충돌 연속 감지, 네이티브 복구 시점과 정상 백그라운드 전환을 검사합니다. 잠긴 노트와 반투명 레이어의 기존 미리보기도 읽지 않습니다.
- 로컬 전체 Debug 테스트 **698개**가 실패·오류·건너뜀 없이 통과했습니다. Android ARM64 네이티브 빌드와 Kotlin 컴파일도 통과했습니다. 화면 재생성은 별도 앱 시작으로 세지 않도록 검사했습니다.
- **기기에서는 확인하지 못했습니다.** 그림이 실제로 제때 보이는지, 실제 잉크로 바뀔 때 어긋나 보이지 않는지, 벤치마크의 펜 이벤트가 실제 펜처럼 처리되는지는 태블릿에서 봐야 합니다.

## 태블릿에서 해 볼 것

1. 획이 많은 노트를 열었다가 나가고 다시 엽니다. 내용이 바로 보이는지, 실제 잉크로 바뀔 때 깜빡이거나 어긋나지 않는지 봅니다.
2. 마스킹 테이프가 있는 페이지는 이전처럼 열리는지(가려 둔 것이 보이지 않는지) 확인합니다.
3. 빈 연습 노트에서 **Run benchmark**를 실행하고 보고서를 복사해 보내 주세요. 성능 힌트, 자체 버퍼 표시 스위치를 하나씩 바꿔 다시 실행한 보고서도 함께 있으면 비교할 수 있습니다.
4. 벤치마크 완료·중지·앱 전환 후 임시 획이 남지 않고 이전 실행 취소·다시 실행 기록이 유지되는지 확인합니다.
