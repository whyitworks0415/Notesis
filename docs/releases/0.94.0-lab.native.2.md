# Notesis Lab 0.94.0-lab.native.2 (235)

<!-- update: manual -->

> C++·Rust 공통 엔진 이전 중간 빌드입니다. **앱 대부분을 이전한 완성판은 아닙니다.**
> 정식 0.94.0(234)을 기준으로 하며 `com.notesis.lab`으로 별도 설치합니다.

## 실제 이전한 부분

- 필기 데이터 파일(NTSS v1~v4)의 읽기·경계 확인·커서를 Rust로 옮겼습니다. 8MB 전체 임시 버퍼 없이 레코드별로 읽습니다.
- v4 전체 저장과 증분 저장을 Rust로 옮겼습니다. 전체 저장은 완료한 임시 파일로 교체하고, 증분 저장은 데이터를 쓴 뒤 개수를 갱신합니다.
- 저장 중 종료되어 남은 미완성 꼬리가 다음 증분 저장 때 중복 획이 되는 것을 막습니다. 중단한 작업의 꼬리는 롤백합니다.
- Markdown Undo/Redo와 타자 묶기·선택 위치를 Rust로 옮겼습니다. 한글·이모지의 UTF-16 위치를 유지하며, 한 타자 묶음 안에서는 매 키마다 문서 전체를 복사하지 않습니다.
- C++은 기존 공간 인덱스·부분지우개 기하·획 후처리와 Rust/Android 사이 JNI를 담당합니다.
- 진단의 **C++ and Rust processing** 스위치로 기존 경로와 비교할 수 있습니다. 비교하려면 변경 후 앱을 완전히 종료했다 다시 시작하세요.

## 유지·미이전 범위

- 정식 0.94.0의 Material 화면·모션·Markdown 블록 편집·AI 첨부·터미널은 유지합니다.
- **Document/Page 모델, 메타데이터 JSON, 저장 스냅샷, 펜 컨트롤러, Compose 화면은 아직 Kotlin입니다.**
- Ink 입력 해독과 Brush/Stroke 생성은 기존 AndroidX Ink 공개 API를 사용합니다.
- 안전 모드·라이브러리 미준비·일부 큰 입력에는 기존 경로를 유지합니다. 기존 코드도 소스 비율 집계에 포함합니다.
- UI까지 네이티브로 바꾸기 전에는 앱 전체의 대부분을 C++·Rust로 옮겼다고 할 수 없습니다.

## 확인

- Rust 단위 시험 13개, 정적 검사, C++ 주소·정의되지 않은 동작 검사 통과.
- JNI를 포함한 JVM 회귀시험 **749개** 통과. 실제 C++·Rust 연결을 통해 버전별 파일·바이트 왕복·동시 읽기·닫힌 핸들·이모지/한글 편집 이력을 대조했습니다.
- Android ARM64 C++·Rust 링크와 APK 빌드 통과.
- 게시용 CI는 전체 JVM·Robolectric 검사를 통과한 뒤에만 서명·게시합니다.
- **실기기 시험과 필기 지연·프레임·발열·배터리 개선 측정은 하지 않았습니다.** 호스트 결과를 앱 성능 향상률로 표시하지 않습니다.

## 시험할 것

1. 복사한 노트에서 필기·부분지우개·Undo/Redo·저장·재열기를 확인합니다.
2. Markdown에서 한글·이모지 입력 후 되돌리기·다시 하기를 확인합니다.
3. 스위치 변경 후 앱을 완전히 재시작하고 같은 노트·주사율·확대율로 비교합니다.
4. 진단의 Rust 읽기·저장·편집 이력 처리 횟수가 증가하는지 확인합니다.

자세한 범위는 첨부한 `Native-migration.md`를 참고하세요.
