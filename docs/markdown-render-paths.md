# Markdown: 무엇이 어디서 보이는가

Notesis의 Markdown은 두 경로로 그려집니다. 하나는 앱 화면(편집·읽기), 다른 하나는 PDF로 만들 때입니다. 한쪽에만 있는 기능을 "앱에 없음"으로 세지 않도록 정리합니다.

| 기능 | 편집(Live/Source) | 읽기(Read) | PDF로 만들기 |
|---|---|---|---|
| 제목·문단·목록·인용·구분선 | 있음 | 있음 | 있음 |
| 할 일 체크박스 | 글자로 | 눌러서 체크(원문을 고침) | 체크 모양으로 |
| 표 | Markdown 글자 그대로 | 표로 | 표로 |
| 앞머리(YAML frontmatter) | 글자 그대로 | "Properties" 상자 | 뺌 |
| 코드 블록 | 고정폭 | 고정폭, 색 없음 | highlight.js로 색 |
| callout `> [!note]` | 글자 그대로 | **0.85.0부터** 종류별 색·제목·접기 | 있음 |
| 수식 `$…$` | 글자 그대로 | 글자 그대로 | KaTeX |
| 위키 링크 `[[노트]]` | 자동 완성·따라가기 | 따라가기 | 표시만(따라갈 수 없음) |
| 포함 `![[노트]]` | 글자 그대로 | 링크처럼 | 표시만, 내용을 불러오지 않음 |
| Mermaid 도표 | 없음 | 없음 | 없음 |
| HTML 직접 쓰기 | 글자 그대로 | 글자 그대로 | 표시함, 실행은 안 됨(아래) |

## HTML의 신뢰 경계 (M03 검토)
PDF 경로는 `marked`로 HTML을 만들어 `innerHTML`에 넣습니다. 그래도 Markdown 파일 안의 스크립트는 실행되지 않습니다.
- 그 WebView에는 앱 쪽 JavaScript 다리(`addJavascriptInterface`)가 없습니다.
- 파일·콘텐츠 접근이 꺼져 있습니다.
- CSP가 `script-src 'self'`라서 앱에 들어 있는 스크립트만 돕니다. 글 안의 `<script>`나 `onerror=` 같은 인라인 스크립트는 막힙니다.
- 네트워크 요청과 다른 페이지로의 이동이 모두 막혀 있습니다.

## 큰 문서
- 읽기는 LazyColumn이라 화면 밖의 블록은 그리지 않습니다.
- 편집기는 글자가 바뀔 때마다 문서 전체를 다시 분석합니다. 어느 길이부터 느려지는지 아직 재지 않았습니다. 바꾸기 전에 기기에서 먼저 잽니다(비교 문서 M02의 권고).
