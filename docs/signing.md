# 서명 키와 비밀번호

## 무엇인가
- **서명 키(keystore, `.jks` 파일)**: APK에 도장을 찍는 열쇠입니다. 안드로이드는 이미 설치된 앱과 **같은 열쇠로 서명된 APK만** 업데이트로 받아 줍니다.
- **비밀번호**: 그 열쇠 파일을 여는 암호입니다. 열쇠 파일과 비밀번호가 둘 다 있어야 서명할 수 있습니다.
- 그래서 이 둘을 가진 사람은 누구든 "Notesis인 척하는 APK"를 만들어, 이미 설치된 Notesis 위에 업데이트로 설치되게 할 수 있습니다.

## 무엇이 문제였나
- 예전에는 열쇠 파일(`keystore/release.jks`)과 비밀번호(`app/build.gradle.kts` 안의 문자열)가 **공개 저장소에 그대로** 올라가 있었습니다.
- 누구나 내려받아 서명할 수 있었고, 앱의 업데이트 확인은 서명이 아니라 패키지 이름과 버전 번호만 봅니다.
- 한 번 공개된 키는 되돌릴 수 없습니다. 저장소를 비공개로 바꾸거나 기록을 지워도, 이미 내려받은 사람의 복사본은 남습니다.

## 어떻게 고쳤나
1. **새 키로 교체**: 새 열쇠를 만들었고, 이 열쇠는 저장소에 없습니다. GitHub의 Secrets에만 있습니다.
2. **예전 키는 "이어받기"로 은퇴**: APK 서명 방식 v3의 *키 교체(rotation)* 를 썼습니다. 새 APK에는 "예전 키 → 새 키"로 이어지는 증명(lineage)이 들어 있어서, 이미 설치된 앱은 그대로 업데이트되고, 그 뒤로는 **예전 키로 서명한 APK가 거절**됩니다.
3. **저장소에서 제거**: `keystore/release.jks`와 `build.gradle.kts`의 비밀번호를 지웠습니다. `.gitignore`가 `*.jks`, `*.keystore`, `*.p12`, `*.pfx`를 막습니다.
4. **빌드가 서명을 확인**: 서명 뒤에 `signing/CERT_SHA256`(공개해도 되는 지문)과 같은 인증서인지 확인하고, 다르면 빌드가 실패합니다.

## 되돌릴 수 없는 것
- 예전 키와 비밀번호는 git 기록(커밋 `598b9d7`)에 남아 있어서 **계속 공개 상태**입니다.
- 새 키로 바뀌기 전의 버전을 쓰는 기기는 그 사이에 예전 키로 만든 가짜 APK의 위험이 남습니다. **모든 기기를 이 키 교체 버전 이상으로 업데이트**하세요.
- 예전 키로 서명한 APK를 *새로 설치*하는 것은 막을 수 없습니다(새 설치는 비교할 대상이 없음). 믿을 수 있는 곳(이 저장소의 Releases)에서만 설치하세요.
- 기록에서 키 파일을 지우려면 git 기록을 다시 써야 하고(`git filter-repo`) 강제 푸시가 필요합니다. 그래도 이미 퍼진 복사본은 없어지지 않으므로 하지 않았습니다. 원하시면 따로 말씀해 주세요.

## 설정 (한 번만)
저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 두 개를 만듭니다.

| 이름 | 값 |
|---|---|
| `NOTESIS_KEYSTORE_BASE64` | 키 파일을 base64로 바꾼 한 줄 |
| `NOTESIS_KEYSTORE_PASSWORD` | 키 파일 비밀번호 |

두 값이 없으면 빌드는 "서명할 수 없음"으로 실패합니다(서명 없는 APK를 내보내지 않습니다).

직접 새 키를 만들고 싶다면:
```bash
keytool -genkeypair -keystore notesis.jks -storetype PKCS12 -alias notesis \
  -keyalg RSA -keysize 3072 -validity 10000
base64 -w0 notesis.jks   # 이 결과를 NOTESIS_KEYSTORE_BASE64에
```
이 경우 빌드가 쓰는 예전 키 이어받기 증명도 새 키 기준이 되므로, `signing/CERT_SHA256`을 새 인증서의 SHA-256(`keytool -list -v`)으로 바꿔야 합니다. 키 별칭은 `notesis`로 만드세요.

## 보관
- `.jks`와 비밀번호를 **저장소 밖**(비밀번호 관리자, 암호화된 USB 등) 두 곳 이상에 보관하세요.
- 잃어버리면 같은 키로 서명할 수 없어, 이미 설치된 앱에 업데이트를 줄 수 없습니다. 모든 사용자가 앱을 지우고 새로 설치해야 합니다(노트는 먼저 **Backup all notes**로 내보내기).
- 새로 유출되면: 새 키를 만들고, 같은 방식으로 이어받기를 한 번 더 하면 됩니다(`apk.yml`의 lineage 단계에 키 목록이 늘어납니다).
